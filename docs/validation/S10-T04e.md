## What was built

**What already held.** The stash *marker*: a script's map spot
(`level.map_add_object_spot_ser`, which the treasure manager uses) reaches
every player and a client entering the world (S08-T09, pq-2: "the stash's
treasure spot on both maps"). The stash *contents*: Anomaly's stashes are
existing level inventory boxes; `treasure_manager.set_random_stash` marks
one with a content string and the spot, and `try_spawn_treasure` spawns the
items into the box when the box is **used**
(`physic_object_on_use_callback`); taking from a box goes through the S08
transfer records (world, first come, journaled).

**A client's USE on a box (T04e-1).** A `CGameObject` is script-usable, so
since patch 0063 a client's USE on an inventory box became the use-object
intent (17) and the local use callback was skipped: the server ran the box's
callback (the treasure spawned there) but the client's own loot window never
opened. The intent is still sent (the server spawns the stash's contents in
the player's context) and the client's local use callback now runs as
well, so the installed Lua loot window opens (`coop_client_use_object`
returns false for a box). The client's own treasure manager spawns nothing
(its caches hold no content strings).

**The take callback (T04e-3).** `CInventoryBox::OnEvent` fires
`actor_on_item_take_from_box` only while a window is open on the same
process, so a client's take never reached the treasure manager on the server
(the stash stayed "unsearched", its spot stayed on both maps). The transfer
adapter (`apply_or_defer`, apply phase) now fires the callback in the
taker's context when an item leaves an inventory box into a participant
actor (`box-take-callback`): the stash's searched state, the spot removal
(to both maps through S08-T09's presentation), news and statistics follow.

**A checkpoint after a stash's contents appear (T04e-2).** The spawned items
are server-made and not journaled: a crash before the next checkpoint would
restore an "unopened" stash while the taken items' records replayed as
no-ops (a duplicate stash). `take_use_object` watches a used box for 20
ticks (`StashWatch`); when its item count grows the server logs
`stash-opened` and requests a publication.

**Fixture (`--stash c1,c2`, profile `stash_party`, server-driven;
`stash_fixtures`).** In player 1's context the treasure manager makes the
nearest open inventory box a stash with a medkit and a bread (the "treasure"
spot reaches both clients); player 1 is placed beside the box when far
(player 1 only, L58); player 1 uses the box (17: the contents spawn, a
checkpoint) and takes one item (7: the take callback fires, the spot goes);
the external kill and restart recover the box's remaining item, player 1's
item and no spot. `compare-coop-stash.py` checks the seven points in its
header.

## Limits found here

- A stash's contents spawn only when a player uses the box (the installed
  rule); a partner who opens the box first gets them (first come).
- The checkpoint after a stash's spawn is the durability of the contents;
  a crash in the tick between the spawn and the checkpoint request offers the
  stash again (as L45 for a use's next-frame work).
