## What the chains keep, and where (source)

- **DoctorX storyline** (`tm_*.ltx` `drx_sl_*` sections, the honcho table
  in `axr_task_manager.drx_sl_honchos_table`): a "meet the next honcho"
  task completes when its info `drx_sl_meet_honcho_<honcho>` is taken away
  (the honcho's dialogue); the next step, `xr_effects.drx_sl_meet_random_honcho`
  (`xr_effects.script:704-783`), picks a friendly honcho, raises the step
  number and gives that honcho's meet task. Its state is **script
  variables on "the actor"**: `save_var(db.actor, "drx_sl_current_honcho" …)`,
  `drx_sl_current_task_number`, `drx_sl_current_task`, the task givers'
  counts and the money tasks' targets (`xr_effects`, `dialogs`,
  `axr_task_manager`: every name starts with `drx_sl_`). `save_var` writes
  `db.storage[id].pstor` of that object (`_g.script:2568`).
- **In co-op** the honcho's dialogue runs in the talking player's context
  (S10-T04a), where `db.actor` is that player's actor: player 2 meeting a
  honcho would write the chain into actor 2's storage, and player 1's next
  step would read actor 0's — two chains. A party task's own accept and
  completion run in the anchor's (player 1's) context (S10-T05b).
- **Living Legend** (`tm_lostzone_ll.ltx`): each step is a task whose
  `condlist` waits for an info portion or an item and whose `on_complete`
  gives the next task and an info (`lttz_ll_find_doctor` →
  `+living_legend_doctor` → `lttz_ll_visit_agro_ug`,
  `+lttz_ll_visit_agro_ug_task`). Info portions are the party's (S10-T04b,
  T04b-1), tasks are the party's (S10-T05b), item checks see the party's
  inventory in a task scope (T05b-5): no script variable on the actor.

## What was built (patch 0083)

- **The compat layer's `save_var` / `load_var`** (`S.story_wrap = 'drx'`): a
  `drx_sl_*` variable on a participant actor is kept on the host actor
  (actor 0, the installed binder's), whoever's context writes or reads it
  (T05c-1); every write calls `campaign.story_changed(name, value)`.
- **`coop_server_story_changed`** logs `story-var` and marks the story
  dirty; **`story_tick`** publishes one checkpoint once nothing else is
  publishing (`story-checkpoint`, T05c-2), since these variables live only
  in the save.
- **Fixture** `--story c1,c2` (profile `story_party`, `story_fixtures`): the
  DoctorX step in player 2's context; player 1 meets that honcho (the meet
  info taken) and the meet task completes; player 1 takes the next step;
  Living Legend's first task given in player 2's context and its info
  given in player 1's; a check of both players' and the host's chain state
  (`story-verify`); a party travel Cordon → Garbage (the sweep's request,
  S10-T03e) and the check again; after `Run-CoopSession -ServerKill`, the
  restarted server checks again. `tools/compare-coop-story.py`.
