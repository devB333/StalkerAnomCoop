# S06-T05 — Basic NPC combat and stage convergence

**Status: Completed (2026-10-21).** Engine `c57fe5b9` + patches 0001–0035;
protocol v1.4 (`proto-build-30`, unchanged; health 0 now means dead). Design:
[co-op session](../coop-session.md#npc-encounter-and-deaths-s06-t05).

## What changed

**Engine (patch 0035)**, 9 files:
- **A participant's death is native on the server** (`Entity.cpp`,
  `CEntity::KillEntity`). The installed before-death callback
  (`bind_stalker_ext.actor_on_before_death`) only reaches the actor with the
  script binder (`db.actor`) and ends in `db.actor:kill(db.actor, true)`. The
  second participant's actor has no binder, so before this its death never
  happened: health 0 and no `Die` (enc-1). On the campaign server every
  participant actor now takes the path that call takes
  (`bypass_actor_check`). The installed game modes that hook the callback
  (Azazel, Ironman) no longer run for participants.
- **Health 0 means dead** (`CoopServerHost.cpp`, `health_of_alive`). A living
  actor or creature is sent at least 1 of 10,000.
- **Clients show deaths with the native `Die`** (`CoopClientLink.cpp`,
  `present_death`): the body falls (its ragdoll), the death sound plays, and
  the own actor gets the death camera. The server already ran the
  consequences, so on a replica `CEntityAlive::Die` skips the scripts' death
  callbacks, the relation change and the killer record (`entity_alive.cpp`),
  and `CActor::Die` skips the single-player game over, which would end the
  level (`Actor.cpp`). A dead body is no longer position-presented, a dead own
  actor is not reconciled, and a creature's health is applied while it lives.
- **The dead take no input** (`CoopServerHost.cpp`, `apply_inputs`): a dead
  actor's input is consumed, counted (`dead_in<slot>` in the status line) and
  not applied; its trigger is released.
- **No level change** (`level_changer.cpp`, `xrServer.cpp`; L14). In enc-9
  actor 0 sprinted into a `k00_marsh` level changer. The server ran the
  native change (`CALifeUpdateManager::change_level`,
  `alife_update_manager.cpp:166-243`: autosave, disconnect, start) and crashed
  (`0xC0000005`) in `CApplication::OnEvent(eStart)`'s `main_menu off`
  (`x_ray.cpp:2913`, `console_commands.cpp:2013`): a headless server has no
  main menu. A non-silent changer would instead open the change-level dialog,
  which pauses the device (`UIGameSP.cpp`, `CChangeLevelWnd::Show`). Now a
  level-changer touch or invitation on the campaign server or a co-op client
  logs `coop level-change-refused` and does nothing, and the campaign server
  refuses `M_CHANGE_LEVEL` (a script or console `jump_to_level`). Plain single
  player (no participant registry, no replica) is unchanged.
- **Fixtures** (`CoopConfig`, `CoopServerHost.cpp`; `prepare-coop-session.py
  --encounter`): `encounter` spawns a `boar_normal` (the S02-T06c monster)
  8–12 m from participant 2's actor, at the reachable node (of 8 directions)
  farthest from Fanat and participant 1, 20 s after both clients send input; `lethal` gives participant 2's actor a lethal wound hit
  from the boar 8 s after the boar died, or 60 s after the spawn while it
  lives, unless that actor is dead already. The server writes
  `coop-encounter.csv` (participants, the boar and Fanat every 100 ms).
- **Encounter program** (`CoopClientLink.cpp`, profile `script = 4`): each
  player sprints 4 s away from Fanat, equips the pistol, reloads, aims at the
  boar every frame while it is within 30 m, holds fire until the boar has
  hurt one of them (or 12 s), then presses fire every 300 ms and reloads when
  empty. After its own death it tries to walk and fire for 2 s
  (`D-dead-walk`, 5 s after death) and sends a forged "revive" intent
  (kind 8) at 8 s.

**Tools:** `tools/compare-coop-encounter.py` (new);
`prepare-coop-session.py --encounter`.

## Checks (`compare-coop-encounter.py`)

| Check | Rule |
|---|---|
| `npc_damage` | a participant's health falls with the boar as last hitter |
| `player_damage` | the boar's health falls with a participant as last hitter |
| `<client> npc_deaths` | every NPC in the record (boar, Fanat) that died on the server is shown dead on the client (`death-presented`) within 1 s; at least one NPC died. The server time is the first dead 100 ms row, so a delay down to −150 ms is sampling |
| `<client> player_death <id>` | every participant that died on the server is shown dead within 1 s and stays dead |
| `<client> dead_inert` | during the dead walk the dead actor moves < 0.10 m on the server and on the client, and the server fires nothing |
| `<client> forged` | the forged revive is refused and the actor stays dead |
| `<client> agreement` | ≥ 95 % of the client's 10 Hz health/alive rows show a value the server held in the 600 ms before, and the last rows equal the server's |
| `spawn` | the boar spawned and every client showed it alive |
| `simulation_rate` | median server tick rate ≥ 45 Hz (5 s windows) |
| `no_level_change` | no native level change on the server (no autosave) |

**Rule changes after seeing data** (all before the final runs):
- *Dead walk +2 s → +5 s* (enc-6, 10 % loss and 100 ms lag): the client's
  ragdoll was still falling 3 s after the death, which `dead_inert` counted
  as movement.
- *Encounter clock from input* (enc-7): clients loaded in about 40 s right
  after a build and the server dropped them at its 15 s silence timeout; the
  20 s now start when both clients send input.
- *Boar beside participant 2* (enc-3…8): Fanat, player 1's companion,
  follows actor 0 and shot the boar before it hurt anyone.
- *Spawn point from 8 directions* (enc-12): participant 2 stood at the
  level's east edge (x 580), the point straight away from Fanat had no node,
  and the fallback put the boar between participant 2 and Fanat, who killed
  it before it hurt anyone. The spawn is now the reachable node 8–12 m away
  that is farthest from Fanat and participant 1.
- *NPC deaths instead of the boar's* (enc-10): the boar killed player 2 and
  Fanat, fled wounded (health 0.24) and outlived the program. Any NPC death
  in the record converging on both clients is what the acceptance needs; the
  boar's is one of them. The `lethal` fallback (60 s after the spawn) keeps a
  participant death in every run.
- *Presented deaths from the client log* (enc-11): player 2 killed the boar
  2 s after it spawned, 45 m from player 1, whose 10 Hz record only follows
  the boar within 40 m and so never listed it. The client's `death-presented`
  line (35 ms after the server) is now the evidence for NPC deaths and for
  the spawn (`present_death` only kills a living body).

## Acceptance

- **NPC and player damage converge:** the boar's hits on player 2 and the
  players' hits on the boar are the server's; both clients show the same
  health in ≥ 99.9 % of rows and the same final state, nominal and at 5 % /
  40 ms and 10 % / 100 ms.
- **Deaths converge:** every NPC death (boar, Fanat) and participant death
  is shown on both clients with the native death within 120 ms and stays.
- **Client prediction cannot overturn outcomes:** a dead client's own actor is
  not reconciled, its walk and fire moved and fired nothing, local hits are
  refused (S06-T04), and a forged revive was refused.
- **Rates and failure limits measured** (above). At 10 % loss and 100 ms lag
  everything still converged; that is the highest impairment tested.

## Carried limits

  out of a player's hand cannot be picked up again (enc-10, combat-15).
- **L08** (friendly fire, god mode): unchanged; NPC hits on the second

- **L11** (installed scripts decide for actor 0): the before-death callback

- **L22** (measured convergence): NPC combat now measured (this report). The

- **L23** (activity fixture): smoke-162 and smoke-163 passed. Unchanged.
- **L24** (client exit access violation): not seen in this task's runs.

## Limits

- **The boar's AI decides whether it attacks:** it hurt a player in 8 of the
  10 runs from enc-10 on; in enc-16 it never attacked and in enc-12 Fanat
  killed it first. Its damage is replicated whenever it happens.
- **Fanat interferes:** he follows actor 0, fights the boar, and when hit by a
  player he punches back; the installed `xrs_facer.script` then always drops
  the punched actor's weapon in slot 2 or 3 (`enable_drop_item = true`, line
  9; lines 267–272).
- **Deaths are in memory only** (plan.md: Stage 7 adapters). A dead player
  stays dead with the death camera; no respawn, spectate or reload, and the
  single-player game over does not run on clients.
- **The killer is not replicated:** a body on a client names itself as its
  killer, and no killer event or relation change runs there.
- **Dead bodies** fall as their own ragdoll on each client; the server's
  corpse position is not followed.
- The second participant's death no longer runs the installed before-death
  callbacks (Azazel, Ironman, and any mod listening there).
- One monster type, one weapon, one host, loopback, simulated impairment only
  (L16), sessions under 5 minutes (L21).
