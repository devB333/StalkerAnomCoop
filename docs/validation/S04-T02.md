## Design

### Where it lives

`protocol/` is a project-owned CMake library built with the Stage 1 pinned
compiler, `/MD`, C++17, the engine's settings (`xrGame.vcxproj`: v143,
`MultiThreadedDLL`, `stdcpp17`; the engine builds without exceptions, so the
public API never throws). Two static libraries:

| Target | Contents | Transport library |
|---|---|---|
| `coop_net` | `transport.h`, `fake_network.h`, shared policy (`src/net/policy.*`), fake backend | none on its include or link path |
| `coop_net_gns` | `src/net/gns_transport.cpp`, the only file that includes GNS headers | `GameNetworkingSockets.dll` via its import library |

How the engine links them (static libraries, or the sources added to its
projects) is decided in S05-T01, where the adapter first meets the engine.

### Interface

`listen(address)`, `connect(address) → ConnectionId`, `send(conn, channel,
bytes)`, `flush(conn)`, `poll(events)`, `close(conn, code, detail, flush)`,
`shutdown(flush_timeout_ms)`, `status(conn)`, `counters()`. Connection ids are
assigned by the adapter and never reused (library handles never leave the
backend). Events are `Connected`, `Message` (payload copied, so it outlives the
transport) and `Disconnected` (reason, wire code, detail). For one connection
they arrive in that order, and a peer's last messages come before its
`Disconnected`.

### Threading (acceptance: callbacks cannot mutate the world)

- A transport belongs to the thread that created it (the simulation thread).
  Every call from another thread is refused (`SendResult::WrongThread`,
  `false`, empty) and counted in an atomic counter.
- Nothing calls into game code. GNS queues status callbacks and runs them on
  whichever thread calls `RunCallbacks()` (`csteamnetworkingsockets.cpp:1714-1757`),
  so with two transports in one process one thread can run the other's
  callbacks. The adapter's callback only routes the notice into its transport's
  locked inbox. It finds the transport by an instance id stored as connection
  user data (inherited from the listen socket). The owner handles the notice in
  its own `poll()`. Dispatch is serialised so one connection's notices cannot be
  reordered between two threads.
- Messages are read only for connections the owner has already seen connect.
- A notice for a destroyed transport frees the connection; one for a closed
  connection is counted as stale and ignored.
- GNS `Init`/`Kill` are global and not reference counted
  (`csteamnetworkingsockets.cpp:2503-2533`). The adapter counts transports and
  kills the library with the last one.

### Delivery classes and overload policy (acceptance: explicit policy)

Each channel is one GNS lane (priority, weight) and has one class. Bounds are
per connection and channel; admission uses the library's lane status
(`GetConnectionRealTimeStatus`) at the last poll plus the bytes queued since.
That estimate only over-counts, and the library is asked again before anything
is refused.

| Class | Library flags | Bound counts | Over the bound |
|---|---|---|---|
| Critical | reliable, no Nagle | queued + sent-unacknowledged | **connection closed** (`Overloaded`, wire code 1002); never a silent drop |
| Bulk | reliable, Nagle | queued + sent-unacknowledged | send refused (`Backpressure`), nothing queued, caller retries |
| Transient | unreliable, no Nagle | queued; plus `max_queue_ms` age | send dropped (`Dropped`, counted stale or backlog) |

`validate()` requires the channel bounds to fit the library's shared send
buffer, so the library never refuses an admitted send (S04-T01 finding 3);
`send_failures` stayed 0 in every test. Transient messages are capped at one
GNS fragment group (16,500 bytes), since GNS would send larger ones reliably
(`steamnetworkingsockets_snp.cpp:322-327`).

Inbound: GNS bounds the receive buffer itself. A reliable message that does not
fit is not acknowledged, so the sender retries; an unreliable one is dropped
(`steamnetworkingsockets_connections.cpp:2757-2770`, `snp.cpp:3836-3841`).
The adapter takes at most `max_messages_per_poll` per connection per poll. It
closes a peer (`ProtocolViolation`, 1003) that sends on an unknown channel (GNS
accepts any lane up to 255, `snp.cpp:1444-1451`), with the wrong delivery class,
or over the channel's size limit. Such a message never reaches the owner.

### Shutdown

`shutdown(t)` refuses waiting connection requests (code 1004) and waits up to
`t` for each connection's reliable data to be acknowledged. It then closes each
connection with code 1004, waits 30 ms and closes the listen socket. The wait
is needed because GNS sends close packets from its own thread
(`ConnectionState_FinWait`, `connections.cpp:3188-3215`), and destroying a
listen socket destroys its accepted connections without one (`:424-452`).
Without it, peers time out instead of learning of the shutdown. Destroying a
transport without `shutdown()` does the same with no flush.

### Fake backend

`FakeNetwork` (`fake_network.h`): virtual time and per-lane queues at the
sender's send rate (strict priority, round-robin among equals; weights
ignored). It has fixed latency, transient loss, bounded receive buffers
(reliable waits and holds its lane, unreliable is dropped), acknowledgements
one latency after buffering, crash with peer timeout, refusal, and linger. It
uses the same admission and validation code as the GNS backend. Differences
are on purpose and listed in the header: no packets or retransmission, and a
crashed peer is detected exactly at the timeout.

## Findings

1. **GNS's simulated impairments survive `Kill`/`Init`.** They are static
   globals (`csteamnetworkingsockets.cpp:43-48`), not reset when the library
   shuts down. Tests must clear them (the GNS rig does on its first transport).
   This does not affect the game, which never sets them.
2. **Closing a listen socket drops its connections without a close packet.**
   Handled by closing each connection first and waiting 30 ms (Shutdown).
   Untested on a real network, where the close packet can also be lost. The
   peer then times out, which S04-T05 covers.
3. **A burst can overload a critical channel before any acknowledgement
   returns.** 64 KB at 256 KB/s takes about 250 ms to send, but 65 × 1 KB queued
   in 8 ms is over the bound immediately (first version of the overload test).
   Critical producers must stay below the send rate and their bound. A
   game-side producer can pace on `status()`, which includes bytes queued since
   the last poll. S04-T03/S05 budgets must account for this.

## Limits

- **One machine, loopback only.** Same limit as S04-T01: real UDP sockets and
  the full GNS stack, but loss, reordering and lag come from GNS's simulator.
  No LAN, internet, NAT or firewall test.
- **No sanitizer.** The pinned v143 install has no AddressSanitizer runtime.
  Races were checked by repetition (3 full runs, 8 more race runs) and
  invariants, not by memory instrumentation.
- The inbox of status notices is not bounded: a flood of connection attempts
  while the owner stalls grows it until the next poll. Rate limiting of
  connection attempts and of inbound intents is S04-T04's.
- Liveness heartbeats, reconnect binding and stale-session replacement are
  S04-T04/T05 (S04-T01 findings 1 and 2). The adapter only exposes the
  timeouts.
- The channel layout in the tests (control, actions, bulk, snapshot, input) is
  illustrative; S04-T03 fixes the protocol's.
- Not yet linked into the engine (S05-T01). The headless server's power
  throttling and `Sleep` granularity (S04-T01 finding 5) still need checking
  there; the test runner opts out the way the probe did.
- Fake backend weights, packets and retransmission are not modelled (see
  `fake_network.h`).
