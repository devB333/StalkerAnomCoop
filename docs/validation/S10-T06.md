## What single player does (source)

- The main menu (`ui_main_menu.script`): **New game** opens the creation
  screen (`ShowFactionUI`, 259–267); **Load** opens the load window
  (`OnButton_load_clicked`, 198–209) listing `$game_saves$`.
- The creation screen (`ui_mm_faction_select.script` `OnStartGame`,
  1683–1764) writes its choices to `axr_main.config` `[character_creation]`
  and calls `self.owner:StartGame()`, which starts `all/single/alife/new`
  (`ui_main_menu.script` 250–257). A co-op client refuses every local start
  (S05-T02).
- The screen's rules (`LoadLoadout`, 1206–1290): the faction's loadout list
  `[<faction>_loadout]` in `items\settings\new_game_loadouts.ltx` (inherited
  from `[shared]`; a faction's own line replaces the shared one of the same
  item), "false" items always given, "true" items picked within
  `[points] total_points_eco_<economy>`, a fourth value the highest economy
  that offers it; the start must be one of `[<faction>_start_locations]` in
  `plugins\new_game_start_locations.ltx`; the money is `[<faction>_money]`.

## What was built (patch 0086)

- **Protocol** (`messages.h`): action kind **27 `kActionSession`**, op 1 list,
  op 2 create and op 4 loadout in parts (at most 8 of 240 bytes:
  "key=value" lines), op 3 load (the campaign id); reasons **43** not the
  owner, **44** unknown campaign, **45** busy (a travel, a sleep or another
  switch), **46** bad choices; **CampaignEvent 20**: the campaign list (type
  1: the owner flag, up to 8 campaigns, newest first) or a switch (type 2:
  the next campaign's id, create or load, its label).
- **The owner** (T01-18): the first key a fresh server accepts, kept in its
  app data `coop-owner.txt` for every campaign it serves (`session-owner`).
- **The campaign library**: `appdata\campaigns\<id>\campaign.ltx` (label,
  level, launch files, times), one per campaign the server served or
  created; the served one is entered at its start and updated at its stop.
- **A create** (the owner): the choices are checked by the creation
  screen's rules on the server (faction, start, name, the loadout's items,
  counts and points); the money is the faction's. A new campaign folder gets
  a profile (`new_game = 1`, a new campaign id, the partner's loadout
  checked against the new faction, else the faction's kit) and an fsgame
  whose `$game_saves$` is that folder; the creator's choices go into the
  server's `axr_options.ltx` (S10-T03f reads them there).
- **A load** (the owner): a campaign of the library that is not the one
  being served.
- **A switch**: the server writes `appdata\coop-relaunch.ltx` (the next
  campaign's launch files), tells every client the next campaign
  (CampaignEvent 20), stops cleanly 2 s later (the clean stop publishes a
  checkpoint) and **exits with 75**; `x_ray.cpp` reads the flag before the
  game stops. Its launcher starts it again on the next campaign:
  `tools/Run-CoopSession.ps1` (logs of each campaign in
  `server-campaign-<n>/`) and the new **`tools/Start-CoopServer.ps1`** for a
  real server. One process serves one campaign, so nothing of one campaign's
  state carries into the next.
- **The partner** (T01-19): its creation screen's Start keeps only its
  loadout (`coop-loadout-<slot>.txt`) for the owner's next new game; faction,
  start and modes are the owner's.
- **The client**: on a co-op client the installed menu's `StartGame` sends
  the choices (`campaign.client_session_create`) instead of starting a game,
  and Load lists the server's campaigns in the standard load window
  (`FillList`, `Update`, `OnListItemClicked`, `OnButton_load_clicked`;
  delete does nothing). A switch notice sets the campaign the client proves
  itself to; the client's reconnect loop joins the new world. Results are
  told on the HUD in plain words.
- **Test driver** (`session_script`): 1 the owner (a list, a create breaking
  the rules, a valid create, then the first campaign loaded back), 2 the
  partner (its loadout through the creation screen's Start, then a load).
  It writes the choices where the screen writes them and calls the
  installed menu's `StartGame`, so the co-op menu code runs.

## Limits found here

- A switch takes the server down for its stop and the next campaign's load
  (about 20 s for a load, about 50 s for a new game with its start move);
  the clients show the loading screen meanwhile.
- The campaign library lists at most 8 campaigns (the newest); a client
  cannot delete one (the operator deletes its folder).
- The owner is fixed per server (`coop-owner.txt`); the operator deletes the
  file to give it to the next key.
- The partner's loadout is chosen before the owner's create and checked
  against the owner's faction; one that does not fit gives the faction's
  kit (logged), and the partner is not told.
- Join is the client's start (its configured server); there is no server
  browser.
- Hands-on: the menus were driven by the test driver (the installed
  `StartGame` and the load window's functions); clicking them is for the
  user's G10 check.
