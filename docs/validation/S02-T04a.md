# S02-T04a — Server clock and serial frame driver

Recorded 2026-10-18 UTC. **Completed.** The campaign server has its own simulation
clock and frame driver, with no render loop, window or input. The fixture used test
probes. No gameplay object, physics world, AI or ALife work ran, because those need
a level (S02-T04b/c). Parent S02-T04 stays In Progress.

## Problem (native source)

`CRenderDevice::FrameMove` (`xrEngine/device.cpp:694-755`) sets the time from the
wall timer:
- **Float time:** `fTimeDelta` is smoothed and clamped to 0.1 s.
- **Integer time:** `dwTimeGlobal` follows wall time.

A long frame therefore silently drops float time while the integer clock jumps.

`on_idle` (`device.cpp:401-578`) also mixes in matrices, rendering and window
work. It runs `seqParallel` and `seqFrameMT` on a second thread, or on the main
thread as a fallback.

The scheduler (`Engine.Sheduler.Update`, `xrEngine/xrSheduler.cpp:442-497`) is
called only from `CGamePersistent::OnFrame` (`xrGame/GamePersistent.cpp:827`), at
priority HIGH+1. It also asserts `Device.Statistic`.

## Change

Patch `0006-campaign-frame-driver.patch`
(SHA-256 `1d00b66f56852445a1d277af967dd3320c0c886d9953bf4a69eae5e4cba2fb48`) adds
`xrEngine/CampaignServerClock.{h,cpp}`, `CCampaignServerClock`:

- **Ticks.** Simulation time moves only in whole ticks (default 20 ms; `-campaign-tick-ms 1..100`).
  Each tick sets these Device fields consistently:
  - `dwFrame` and `Core.dwFrame`
  - `dwTimeDelta` and `dwTimeGlobal`
  - `fTimeDelta`, and `fTimeGlobal = dwTimeGlobal/1000`
  - `dwTimeContinual` (set to simulation time)
- **Tick order:**
  1. the clocks
  2. `Device.seqFrame` in native priority order
  3. queued `seqParallel` jobs, each exactly once
  4. `seqFrameMT`, run serially
- **Scheduler slot.** With no game persistent object, the driver registers the
  scheduler update at HIGH+1, the native persistent slot. It creates
  `Device.Statistic` (a `CStats` of counters) if none exists. When a persistent
  object exists (S02-T05), it keeps its own scheduler call and the driver adds none.
- **Catch-up.** Wall time sets how many ticks are due. At most 1 + 5 ticks run per
  call, and any further debt is dropped, counted and logged.
- **Pause.** Pause is an explicit state. Paused wall time is never owed to the
  simulation. The service starts paused, so loading time doesn't become debt.
- **Campaign smoke.** A `frame-driver` service runs after the registries. A
  `frame-driver-fixture` check runs after the model fixture.

The physics `fixed_step` (10 ms, `xrPhysics/Physics.cpp:47`) is unchanged. Physics
will substep inside a 20 ms tick through its own accumulator (S02-T04b).

The series reconstructs all 25 changed files in `builds/stage2/patch-check-07b`
(`builds/logs/patch-reconstruction-07.json`).

## Fixture

The fixture runs 300 ticks: wall-paced, with an injected 500 ms stall at tick 100
and a 300 ms pause at tick 200. It uses test probes:
- `pureFrame` probes at HIGH+1000, NORMAL and LOW, and in `seqFrameMT`
- a `seqParallel` job queued every tick
- a real `ISheduled` probe (t_min 20, t_max 100) registered with `Engine.Sheduler`

It requires:
- every tick's callback order is `1 [2] 3 4 5 6`
- the clocks stay consistent
- one scheduler update and one parallel job per tick
- scheduled elapsed time is bounded by simulation time
- the stall runs exactly 6 ticks and is the only dropped time
- no ticks and no scheduled work run while paused, and resume adds no burst

## Limits

- **No real work driven yet.** Only probes ran. Objects, AI, ALife, physics
  substeps and the server activity policy are S02-T04b/c, and need a level.
- **Catch-up bound not measured.** The bound (5 ticks) and the 20 ms tick are
  starting values chosen without measuring real simulation load. S02-T04c must
  measure and justify them.
- **Serial only.** `seqParallel` and `seqFrameMT` run on the main thread. Worker
  threads need measured ordering and explicit joins.
- **No multi-tick pause scenario yet.** Wall pacing uses `Sleep`, so a tick can be
  up to a scheduler quantum late. That counts as small debt and is caught up within
  the bound. Pause and resume have been exercised, but there's no lifecycle test
  that holds a paused state across several ticks.
