# S05-T03 — Display both participants with separate local views

Recorded 2026-10-20 UTC. **Status: Completed (2026-10-20).** Source
`builds/build_1/engine-work` at `c57fe5b9` with patches 0001–0029; protocol
v1.1 (`proto-build-15`). Design:
[co-op session, participant views](../coop-session.md#participant-views-s05-t03).

## Question

Plan.md S05-T03: bind each client view to its own authoritative participant;
render the remote actor's equipment and pose through reusable replication
interfaces; keep independent input collection and local UI.
**Acceptance:** each player sees both distinct actors and controls only its
own input context; client camera choice never changes the server
participant. **Validation:** simultaneous two-client observation and
independent camera/input checks with recorded build ids.

## What was built

- **View:** each client's player entity is its own participant's actor (the
  replica's player flag, S05-T02), so its first-person camera, HUD and input
  are that actor's. The other participant's actor is drawn whole
  (`CActor::renderable_Render` treats only the local player as first person on
  a replica) and made visible as the network import would.
- **Input → server:** a replica client moves no actor itself
  (`controls_actor` false). Each frame (≤ 60 Hz) the link reads what the
  native control path would read — movement keys, stance, walk, the camera's
  yaw and pitch — sends it as an `InputBatch` (one new input, up to 8 kept for
  loss) and clears the keys as that path would. The server takes the fresh
  inputs (`FreshInputs`), holds the newest for 250 ms, and before every tick
  writes it into the actor's control state (movement bits, camera angles) —
  only for the actor its session's context resolves to (`Scope::Self`);
  detached or silent players get no input. The server's own control path
  then moves the actor with native physics.
- **Snapshots:** 20 Hz, both participant actors (transform with body yaw,
  velocity, health, movement state); each client keeps a short buffer per
  actor by server time, renders 100 ms behind the server's clock and
  interpolates (`CActor::replica_present`: position, body yaw, movement state
  driving the native leg/torso animations). No prediction (S06-T03).
- **World clock:** once a second and on any weather change the server sends
  its game time, time factor and weather (`CampaignEvent` kind 1); clients
  step their ALife clock when more than 3 s of game time apart and take the
  server's weather. Added after the user saw different skies in view-10.
- **No client gameplay scripts:** on a replica no script binder updates, the
  player's own included (view-3: a client-side loot script's
  `alife():create` was refused, the engine binding dereferenced the null and
  Anomaly's error dialog paused the client). Binders still attach (`db.actor`
  for the UI). The create bindings are null-safe.
- **Unattended clients:** profiles turn off the post-load key prompt and keep
  windows active without focus (`keypress_on_start off`,
  `g_always_active on`); a pause left over from the menu is released when the
  world goes live. Test driver (`script = 1`): face the other player,
  screenshot, walk back 1.5 s (slot 0 first, slot 1 six seconds later),
  face again, screenshot. `tools/compare-coop-actors.py` checks ownership and
  presentation.

## Limits

- **Responsiveness:** a player's own movement waits for the server (input →
  next tick → snapshot → 100 ms render delay): no prediction or
  reconciliation (S06-T03); interpolation, rates and baselines are S06-T02's.
  Look (camera) is local and immediate.
- Movement only: no fire, use, jump, lean, inventory or other action reaches
  the server (S06-T04, S08). Movement is not validated beyond the native
  physics (S06-T01).
- NPCs and items do not move on clients after spawning (S06-T02); only the two
  participant actors have snapshots.
- No gameplay script runs on a client, its own actor's included: script-driven
  HUD elements, news and similar presentation that depends on per-frame
  updates are off until a presentation split (S08/S10). Weather effects
  (storms, emissions' visuals) are not replicated, only the weather section.
- The player-2 actor's display name and faction are what the engine gave a
  new actor entity, not the player's chosen name.
- Rare access violations at a client's exit (2 of ~40 client runs, after the
  replica ended); not reproduced on demand.
- One host, loopback, two clients.
