## What is not covered (carried)

- **Inventory, quests, rewards are not durable** (L36): nothing beyond the
  synthetic ledger, deaths and respawns has a record or an adapter; a
  restart rolls them back to the last generation. Stage 8 gives each its
  record, adapter and crash test under this contract.
- **Actor 2's script state** (L32) and **captured contexts / presentation
  outboxes** (L33) are not persisted.
- **The world serialization stays on the simulation thread** (L34, revised):
  45–65 ms per checkpoint, up to 129 ms seen; a client sees about a 100 ms
  pause at a checkpoint. A further task (incremental serialization) only if
  play still shows a hitch.
- **Durability is process-termination durability** (L35): no power-loss
  test; one previous generation retained.
- **Looting the corpse** needs inventory transfers (S08-T02). The respawned
  actor carries the faction kit's always-given items and the dead actor's
  identity and money; the optional loadout picks of the new game are not
  recorded by the installed scripts and are not re-given.
- The K4 ownership class (an item consumed from an NPC's inventory stays on
  clients) is unchanged by Stage 7.

## Decisions for the user (answered below)

1. **Checkpoint cadence.** `checkpoint_seconds` is a profile key (tests used
   30–60 s). A shorter cadence bounds the rollback but stalls the tick more
   often (L34); the join and clean-stop publications are unconditional.
   Proposed default for play: 120 s until L34 is engineered away.
2. **Respawn point.** The latest published generation's position for the
   player's actor (else the last place the server saw it alive, else beside
   the corpse). With a 120 s cadence a player may respawn up to two minutes
   of movement behind where they died. Accept, or add a "respawn at the
   death spot" option?
3. **Respawn kit.** The new actor carries the `actor` section's supplies.
   The faction loadout (as the user decided at G06) needs the loadout
   scripts to run for a second participant (L32): accept the section's
   supplies until the script split, or make S08 give the kit natively?

## User decision

2026-10-23, before acceptance (the report stays open until the three items
below are done and re-validated):

1. **No hitching.** "We need to move it to a different thread, there can't
   be any hitching." Checkpoint publication must not stall the simulation
   thread: new task **S07-T08** (added by user decision at G07) moves the
   save's compression and file write and every store step to a worker
   thread; only the world serialization and the scripts' `.scoc` write stay
   on the simulation thread, measured and reported. L34 is owned by S07-T08
   instead of S11-T01.
2. **Respawn point:** "at the entrance to each level from where they
   entered from." Each participant's level entry point (where its actor
   first stood on the level: the start for the saved actor, the join spawn
   for a joining player, the level changer's arrival in Stage 9) is recorded
   in the supplemental record and is the respawn point (S07-T07 revision).
3. **Respawn kit:** "just give the faction kit again." The respawned actor
   keeps the dead actor's community, name, rank and reputation and receives
   the faction's new-game starting kit (S07-T07 revision).

Re-validation (2026-10-23, campaign-238 / client-138, `proto-build-37`):

1. [S07-T08](S07-T08.md): publication runs on a worker thread; the
   simulation thread keeps only the world serialization (45–65 ms, twice
   119–129 ms in rec-4). On the client the gap in server updates at a
   checkpoint fell from 183–367 ms to about 100 ms (one 168 ms), the
   interpolation buffer. Recovery (rec-4) and the `checkpoint:*` matrix
   points (mx3) pass with the asynchronous publication. L34 is updated with
   these numbers; a further serialization task is proposed only if play
   still shows a hitch.
2. [S07-T07](S07-T07.md) death-3/death-4: the respawn point is the
   participant's level entry point, recorded in the supplemental record
   (schema 2) and restored across restarts.
3. death-4: the respawned actor carries the faction kit (13 items and the
   pistol's ammo for `stalker_loadout`) with the dead actor's community,
   name, rank, reputation and money.

Acceptance itself: pending the user's word.
