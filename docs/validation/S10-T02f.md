## What was built

Anomaly's companions are the installed `axr_companions` scripts: the
dialogue action `dialogs_axr_companion.become_actor_companion` puts the
NPC's squad into `axr_companions.companion_squads` and gives each member the
companion logic (`beh_companion.ltx`, scheme `axr_beh`), which follows,
waits and fights around `db.actor`; the squad's script target is `"actor"`,
id 0. On the server id 0 is the host's actor, and outside a dialogue
`db.actor` meant the nearest player (S10-T02a), so player 2's companion
would have walked to player 1.

**A companion belongs to the player who recruited it (T02f-1).** The
server's compatibility layer (`CampaignScriptContext.cpp`, the same
mechanism that wraps `CGeneralTask.check_task`) wraps three installed
functions:

- `axr_companions.add_to_actor_squad` (every recruit path calls it): in a
  participant context it records that player's slot in the NPC's script
  vars (`se_save_var … "coop_recruiter"`, saved with the game) and in the
  engine's companion registry (`campaign.set_companion`);
  `remove_from_actor_squad` (dismissal) clears both.
- `sim_squad_scripted.get_script_target`: a companion squad's target 0
  becomes its recruiter's actor (`campaign.slot_actor_id`); with the
  recruiter away the squad holds where it is.
- `dialogs_axr_companion.is_actor_companion` (the companion command
  dialogue's precondition): false in the other player's context.

**The NPC evaluation scope covers the planner (found by companion-3).** A
stalker's scheme actions (`axr_beh`'s `execute`: `set_desired_target`,
`beh_move`) run from its planner (`CAI_Stalker::Think` → `brain().update`),
not from its script binder update, where S10-T02a opened the scope. The scope
now also wraps the planner and `ProcessScripts` in `CAI_Stalker::shedule_Update`
and `CCustomMonster::shedule_Update`, so every NPC's scheme actions see the
same `db.actor` as its condlists (the nearest participant, or a companion's
recruiter).

The engine's NPC evaluation rule (`npc_evaluation_actor`, S10-T02a) answers
a registered companion's `db.actor` reads with its recruiter while that
player is alive and present (`companion_reads` counter). The installed
scripts also reach the actor by its story id (`get_story_object("actor")`,
registered for actor 0, the host's; `axr_beh` walks to it): the compat layer
answers that story id like `db.actor`, the evaluated NPC's player (a
companion's recruiter, else the nearest) or the open context's. After a load the
registry is rebuilt from the saved script var the first time the squad's
target is asked for.

**A recruit is durable (T02f-3).** The registry's change calls the server
(`coop_server_companion_changed`), which logs `companion-changed npc= slot=
published=` and asks for a checkpoint, as a stash's spawn does (S10-T04e).

**Fixture (`--companion c1,c2`, profile `companion_party`, server-driven;
`companion_fixtures`).** The nearest alive stalker to player 2 with a
squad, not a story NPC, not already a companion and not hostile to player
2, is recruited in player 2's context through the installed dialogue
action. Checks: its recruiter slot is player 2's; player 1 is put 4 m from
it (player 1 only, L58) and inside its evaluation scope `db.actor` is still
player 2; the command dialogue's precondition is false in player 1's
context and true in player 2's; its squad's script target is player 2's
actor; then it walks to player 2 (within 8 m in 120 s). With
`-ServerKill` the restarted server's fixture finds the companion in the
companion squads by its saved recruiter (`restored`) and runs the same
checks. `compare-coop-companion.py` checks the six points in its header.

## Limits found here

- The companion hotkeys and the companion wheel (`axr_companions`
  `on_key_release`, `start_CW`: the `cycle_companions_*` modes and the
  wheel's per-squad settings and move-to-point) run in the pressing
  client's own Lua and do not reach the server (T02f-5); orders through a
  companion's dialogue do.
- The companion inventory window (`ui_companion_inv`) is not exercised.
- On a level change the installed script moves companion squads to the
  host's arrival point (`on_level_changing`, `alife():actor()`); both
  players travel together (S09), so they arrive at the same passage.
