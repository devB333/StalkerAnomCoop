# S08-T05 — Commit shared objectives and rewards once

**Status: Completed (2026-10-25).** Engine `c57fe5b9` + patches 0001–0047
and the S08-T04…T06 changes (patch 0048); protocol `proto-build-42`.
Builds campaign-265 / client-165 (q-5, q-6) and campaign-266 / client-166
(the final set, [S08-T06](S08-T06.md)). Spec: [persistence
contract](../persistence-contract.md) §8a.

## Rules

| Case | Canonical order / rule | Where |
|---|---|---|
| Two contributions | each patch is a pickup (S08-T01: one owner, durable); the pooled count is the server's at its check, so the order of contributions is the server's arrival order and only the total matters | `campaign_party_count`, the adapter's status functor |
| Two accepts | the first in the server's tick order gives the task; the second is refused `QuestActive` (16) | `take_quest` op 1 |
| Two turn-ins (simultaneous completion) | the first starts the completion; a turn-in for the same task while it is pending **joins** it: one completion, one set of effects, every waiter answered Accepted with that completion's commit | `take_quest` op 2, `PendingTurnIn.waiters` |
| Repeated delivery | a request still in progress gets one answer, later; a completed one returns its stored outcome (the same commit), after a restart too (the index travels in the generation) | the pending checks before the index lookup |
| Disconnected contributor | its retained actor stays in the party: its patches count and it is paid for them | `sync_party_actors` (bound links) |
| Quest-NPC death | the server's dialogue is atomic within one tick (there is no open dialogue the giver could die in); a dead giver is refused (15) for accept and turn-in | `take_quest` validation |
| Conflicting choices | this quest has none (no branch, no cancel op in this slice) | — |
| Rewards | resolved once by the adapter, applied once by the server; the policy is the user's (S08-T04): money per own patches, goodwill to both, one stash | `apply_party_effects` |
| **Commit before acknowledgement** | an accept or a completion is answered only after a checkpoint generation that holds it is published (contract §8a, E′) | `quest_answers`, `answer_quests` |

Why a checkpoint and not a journal record: the accept and the completion
change the native task, the installed task manager's Lua state, the
anchor's portable store, the stash and the relation registry together. No
adapter could rebuild that from a record without re-running installed,
non-deterministic code (the random count, the random stash). The native
save already holds all of it, and S07-T08 publishes it without stalling
the simulation (the take is ~45 ms). The answer waited 5–8 ticks
(0.10–0.16 s) for its publication in q-5, q-6 and qn-1.

## Validation

| Run | Case | Result |
|---|---|---|
| q-2 (S08-T04) | repeated delivery | the turn-in's same-id repeat returned the original commit |
| q-5 | two turn-ins at the same tick | `quest-turnin-joined … waiters=2`; one `quest-completed … waiters=2`; both answered Accepted with commit 1596 after generation 4; patches 4/5, paid 2,968 / 4,185 RU, +75 goodwill to both |
| q-6 | disconnected contributor | p1 dropped its connection; p2 turned in: p1's 6 patches taken from its retained actor and paid (4,793 RU) |
| q-5, q-6 | dead giver | a stalker spawned and killed beside the players; asking it for work refused 15 |
| every run | commit before acknowledgement | every Accepted quest answer logged `answered after generation <G>` with `<G>` a published generation (`answered_after_publication`) |

The crash windows (after the accept, after the completion's effects, after
the publication) are S08-T06's matrix.

## Limits

- **A party quest's outcome waits for a publication:** if the store has
  failed closed the answer is `StoreFailed` and the server stops, as for
  every critical outcome.
- **Conflicting choices** (a branching dialogue, a cancel) are not part of
  this quest; S10-T04 owns dialogue choices.
- **The anchor's death** with the task active is not defined beyond what the
  installed task does (the task stays on participant 1's participant; its
  portable store goes with the old actor object): untested.
