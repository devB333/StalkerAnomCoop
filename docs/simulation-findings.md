# Simulation and level investigation

Source-only investigation at `engine/xray-monolith`, revision `c57fe5b9fab4fe0506659db03137c52d2500eb2f`. All paths below are relative to that checkout. No engine build or runtime execution was performed; source correspondence with installed binaries remains a separate prerequisite. Line ranges refer to this exact revision.

## Decision

An authoritative native Monolith simulation is a credible engineering direction, **not a verified functioning headless server**. Retained dedicated-server conditionals provide useful seams, but renderer/device services and campaign logic require separation. Begin with two players on the same loaded level. Concurrent fully simulated different levels are not supported by the inspected architecture; offline ALife across the world does not supply another online level with physics and actors.

## Ranked blockers and proposed investigation gates

1. **Execution and ownership split:** native online entities, physics and scripts currently live in a game level with HUD/device services. Trace `CLevel::net_Start`, `CEngineAPI::Initialize`, device create/load, `IGame_Level::OnFrame`, and `CPHWorld::Create`; build a dedicated configuration only after implementation authorization. Acceptance: load one copied-data level, advance AI/physics/scripts with no interactive actor or renderer, save and reload without a client.
2. **Single actor ALife anchor:** generalize `CALifeGraphRegistry::update/setup_current_level` and online switching to a participant set. Acceptance: AI and switching remain active near either actor, including distant separation in one level and one disconnection. No evidence here proves the existing scripts tolerate this.
3. **Campaign tasks and scripts disabled on dedicated path:** identify authoritative versus UI task side effects and level script dependencies before lifting guards. Acceptance: a native/Lua quest transition can execute and persist server-side without a HUD actor.
4. **One online level:** phase one design should require party transition. Fully independent cross-level players require separate workers or extensive globals-to-context conversion. Worker approach also needs ownership handoff, global ALife coordination, cross-level quest consistency, time synchronization and failure fencing; it is not a free extension of legacy networking.
5. **Save preparation trusts client world state:** inspect ClientSave, entity net_Save and script state serialization, then design authoritative checkpoint assembly. Snapshot plus committed event log is a proposed persistence layer, not existing functionality. Replaying input is not known deterministic; log accepted canonical state changes and test replay completeness.

## Unresolved evidence

No successful dedicated build, runtime simulation, CPU/memory measurement, headless boot, two-actor ALife run, cross-level run, or server save round trip exists from this investigation. No binary-level proof of these paths in the installed executable was obtained by this source-only subtask. No promise of seamless independent cross-level play is justified. Next useful evidence is a reproducible matching source build and a measured isolated headless execution experiment after authorization, with all game writable paths redirected to the development workspace.
