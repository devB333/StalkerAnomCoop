## What the engine does (source)

- The ALife switch rules measure every object's distance from the one ALife
  actor, `CALifeGraphRegistry::actor()` (the `M_SPAWN_OBJECT_ASPLAYER` entity,
  `alife_graph_registry.cpp:53-57`): `CSE_ALifeDynamicObject::try_switch_online`
  brings an object online when the actor is within `online_distance`
  (`alife_dynamic_object.cpp:160`) and `try_switch_offline` takes it offline
  beyond `offline_distance` (`:180`); the online-offline groups (the squads)
  test every member the same way (`alife_online_offline_group.cpp:226,263`),
  the monster groups too (`alife_group_abstract.cpp:164`). The distances come
  from `alife.ltx`: `switch_distance = 750`, `switch_factor = 0.1`, so online
  675 m and offline 825 m on k00_marsh (`alife_switch_manager_inline.h:36-40`,
  smoke-117 activity meta). The loop is `CALifeUpdateManager::update_switch`
  over the level registry with a process-time budget
  (`alife_update_manager.cpp:92-100`), run from `update()` which the campaign
  clock executes on the tick thread (`mtALife` is on by default,
  `console_commands.cpp:316`; `CampaignServerClock.cpp:151` runs
  `seqParallel`).
- The actor's server entity position the rule reads is updated from the
  actor's own `net_Export` through `ClientSend` and `Process_update`
  (`Actor_Network.cpp:93-101`, `Level_network.cpp:179-227`,
  `xrServer_process_update.cpp:41`); `CActor::net_Relevant` is true for a
  local alive actor, which every participant actor on the server is
  (S03-T03).
- Awareness: a monster adds "the player" as an enemy when the player watches
  it while it remembers a dangerous sound, or when the player is within its
  feel distance and watches it (`monster_enemy_memory.cpp:64,108`, `g_actor`);
  otherwise enemies come from its own visual, sound and hit memory, which is
  generic. The actor's vision is a scheduled `vision_client`
  (`vision_client.cpp:77-101`, `CActorMemory`), so every participant actor's
  visual memory updates on the server. Stalker enemy selection is generic
  (`CAI_Stalker::useful`, `ai_stalker_misc.cpp:86`; relations through
  `tfGetRelationType`); `LookAtActor` tested `Actor()` after choosing the
  nearest participant (`ai_stalker.cpp:1679,1694`). The `g_actor` sight
  actions in `stalker_alife_task_actions.cpp:85,263` are inside
  `#ifdef GRENADE_TEST` (undefined at `:42`), dead code.
- Player-bound abilities (the S03-T02 audit list): several dereference
  `Actor()` on paths reachable whenever such a monster is online and alive,
  which faults on the server with two participants (`Actor()` refuses):
  `anti_aim_ability.cpp:265` (`!g_actor || !Actor()->g_Alive()`),
  `controller_psy_hit.cpp:59,68` (`check_start_conditions`), `:212-218`
  (`check_conditions_final`), `burer.cpp:252` (`StaminaHit`), `:544`
  (`actor_is_reloading_weapon`), `poltergeist_telekinesis.cpp:56`
  (`update_schedule`), `monster_aura.cpp:56` (`calculate`, also behind
  `CBaseMonster::get_psy_influence` and friends),
  `bloodsucker_predator_inline.h:96` (`check_start_conditions`).

## Change (written, unbuilt)

- `alife_switch_manager.{h,cpp,_inline.h}`, `alife_update_manager.cpp`:
  `refresh_activation_anchors()` at the start of `CALifeUpdateManager::update`
  snapshots the alive participant actors' server entity positions on the
  server (`campaign::participant_actor_entities`); `activation_distance(p)`
  returns the distance to the nearest one. On a client, or with no alive
  participant actor, it reads `graph().actor()->o_Position` live, exactly the
  engine's expression, so the client's behaviour is unchanged.
- The five switch sites call `activation_distance` (`alife_dynamic_object.cpp`,
  `alife_online_offline_group.cpp`, `alife_group_abstract.cpp`).
- `CampaignActorAccess.{h,cpp}`: `participant_actor_entities`.
- `monster_enemy_memory.cpp`: both player rules run over
  `campaign::participant_actors` (one local actor on a client, both on the
  server). `ai_stalker.cpp:1694`: the chosen participant.
  `bloodsucker_predator_inline.h`: any participant watching.
- Explicit no-ops while `Actor()` refuses: `anti_aim_ability.cpp`,
  `controller_psy_hit.cpp` (two conditions), `burer.cpp` (two functions),
  `poltergeist_telekinesis.cpp`, `monster_aura.cpp` (strength 0). Each marked
  `S03-T04`.

Policy decisions to record in `docs/participant-identity.md` once validated:
the activation set is the alive participant actors (the same rule as the
activity anchors of S02-T04c, `CampaignServerStart.cpp:150`); a dead or
released participant actor contributes nothing; a detached participant's
retained actor still counts (its release policy is S04-T05).
