## Design and source

The source paths were mapped by tracing `model_Create` through
`CModelPool` and each visual's `Load` (pinned `c57fe5b9`). On DX11, every
CPU array that picking and physics need is copied into memory before any GPU call:
- vertices `Vertices1W..4W` (`Layers/xrRender/FSkinned.cpp:476-479`, `524`, `570`, `618`)
- indices `m_Indices` (`SkeletonX.cpp:746-758`)
- bone faces `_CollectBoneFaces` (`FSkinned.cpp:806-965`)

Nothing is read back from the GPU. Patch `0005-cpu-only-models.patch`
(SHA-256 `1a31b456a46ff76899745dbc1e779d384b073c275e341705a18b4a35b848d480`) makes
these changes:

- **Renderer module.** `CEngineAPI::AttachRendererWithoutDevice` runs the static
  R4 module attach. That only sets pointers and registers console commands
  (`Layers/xrRenderPC_R4/xrRender_R4.cpp:15-25`). `Device.ConnectToRender`,
  `Device.Create` and `CRender::create` never run.
- **Model pool only.** `IRender_interface::cpu_models_create/destroy/stats`. The R4
  implementation asserts there is no `HW.pDevice` and no existing pool, then
  creates only `CModelPool`. Other renderers return false, which fails the stage.
- **GPU chokepoints, skipped and counted** while `CpuOnlyResources::Enabled()`:
  - visual shader creation (`FBasicVisual.cpp`, `SetShaderTexture`)
  - `resptrcode_geom::create` (`Shader.cpp`)
  - `dx10BufferUtils::CreateBuffer` (which returns a null buffer with `S_OK`)
  - Buffer statistics now ignore a null buffer.
  - A level shader id on a CPU-only model is an explicit assertion.
- **Bone materials.** Without `g_pGamePersistent`, `CModelPool::Instance_Load`
  calls an explicit registrar, and asserts if there is none. Registration is
  never skipped. The registrar is the same `RegisterModelMaterials` that
  `CGamePersistent::RegisterModel` now calls (`xrGame/GamePersistent.cpp`).
- **Graphics-absence check.** It now allows the attached renderer module, but
  requires no window, no `Device.m_pRender`, no ready device, no input and
  `HW.pDevice == nullptr`.
- **Campaign smoke.** A `cpu-models` service runs first. The native pool exists
  before persistent construction, so it starts ahead of the spatial DBs. Then
  `cpu-model-fixture` runs after the services. `-campaign-models a,b`
  (launcher `-Models`) overrides the fixture models, and the test-only
  `-ExpectModelFailure` expects a missing model.

The client never enables the CPU-only mode; its model and buffer paths only gain
null checks and the registrar fallback. The series reconstructs all 23 changed files
in `builds/stage2/patch-check-06b` (`builds/logs/patch-reconstruction-06.json`).

## Limits

- **Load only.** No bone transform, animation, `PickBone` ray or physics shell has
  been evaluated. The values aren't yet compared to a client capture (S02-T03c/d).
- **Fixture models.** The actor and NPC models are representative files, not the
  saved actor's outfit visual. That needs ALife (S02-T05/T06).
- **Graphics absence.** Checked as `HW.pDevice == nullptr` and engine state. The
  process still links `d3d11.dll`; there is no API-level trace (H03, S02-T05).
- **Bone evaluation dependencies.** Evaluating bones depends on the device clock,
  and on camera state through `OPTIMIZE_CALCULATE_BONES`
  (`Layers/xrRender/SkeletonRigid.cpp:29-86`). S02-T03c must address both,
  with the S02-T04 clock.
- **Client.** Built but not run interactively.
