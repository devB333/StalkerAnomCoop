## What changed (patch 0030)

`0030-coop-rejoin-input.patch` (SHA-256
`0868929701ad39f154bc70d424ae3556a113a9bf679791451583231e3e163c6c`, 2 files;
reconstruction `builds/stage2/patch-check-33b`,
`builds/logs/patch-reconstruction-33.json`, 222 source files byte-equal):

- **Rejoin input fix** (`CoopServerHost.cpp`, `on_joined`): input sequence
  numbers come from the message header, which restarts on every connection.
  The server kept each player's last taken sequence across connections, so
  after a rejoin every new input looked older than the previous connection's
  last one and was dropped. session-1 showed it: c2's rejoin walk moved its
  actor **0.00 m**, the server counted 3,499 stale input batches and the
  client's acknowledged input stayed at 3,499 (the first connection's last).
  The player would have been frozen for about a minute, until the new
  connection's sequence passed the old watermark. The server now clears the
  watermark and held input on every join.
- **Test driver** (`CoopClientLink.cpp`): a client that was alone at both
  facings (the other player joined later) faces the other actor 3 s after it
  appears and takes one more screenshot (`other-joined`). In session-1 c1's
  facings ran before c2 joined, so its screenshots had no player 2. In
  session-2 c2 joined earlier and c1's second facing found it, so the extra
  step did not trigger.

`tools/compare-coop-actors.py` now also checks a rejoined client's first run
(`cN-first-run`).

## Limits

- **Not a playable campaign.** Movement is the only action; no fire, use,
  jump, inventory or dialogue from a client (S06-T04, S08). No prediction:
  a player's own movement waits for the server (S06-T03).
- NPCs and items do not move on clients after they spawn (S06-T02); only the
  two participant actors have snapshots.
- No gameplay scripts on clients. Player 2's client shows a local "Mission
  complete: Training Day: Boar Hunting" news item and logs
  `CRandomTask:task_fail/task_complete task_fanat_training_1 task is nil`
  shortly after it goes live (also in S05-T03 view-11; never on player 1's
  client). The text is not in the installed `scripts.db0` or the engine
  source, and its origin was not found. It is local presentation only: client
  outcomes are refused. Owner: the presentation split (S08/S10).
- Player 2's display name, faction and look are what the engine gave a new
  actor entity, not the player's own.
- Short sessions (under 5 minutes), one host, loopback, one level.
- Rare client access violation at exit (none in session-1/2); the client
  ALife scheduler stall (S05-T02) is still open.
