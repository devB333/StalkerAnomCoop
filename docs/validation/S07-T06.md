## Deliverable (patch 0042)

- **The termination matrix harness.** Profile keys `failpoint = <point>`,
  `failpoint_count = N` (and `failpoint_fail = 1`) arm a `coop::store`
  failpoint after recovery: on its N-th hit the server terminates itself
  (`TerminateProcess`, exit 0xDEAD) or, in fail mode, the store call fails
  ("disk full"). Engine boundaries: `commit:before-append` (fail mode: the
  store fails closed), `commit:after-flush`, `commit:after-apply`,
  `commit:after-ack` (the ledger), `death:before-append`,
  `death:after-commit`, `respawn:before-append`, `respawn:after-commit`,
  `respawn:after-apply`, `respawn:after-ack`; store boundaries:
  `checkpoint:after-temp/-rename/-manifest/-rotation/-pointer`,
  `append:*`, `write:*`, `rename:*`. `tools/prepare-coop-session.py
  --failpoint point[:count][:fail]` writes the armed profile and a
  failpoint-free `coop-restart.ltx`; `Run-CoopSession.ps1 -ServerKill 0`
  restarts the server after it exits by itself; `tools/run-recovery-matrix.py`
  runs one session per point and checks each with
  `tools/compare-coop-recovery.py` plus per-point expectations.
- **The representative durable death adapter** (Stage 6's deaths): every
  `CEntityAlive::Die` of an ALife object on the serving server commits a
  `death` record in its tick (slot or 0xff for an NPC, the entity, the
  killer, the position; `coop-deaths.csv`; `death-committed`) before the
  death's consequences run. At recovery a record whose entity the checkpoint
  still holds alive is re-applied by `KillEntity` on the live object (or
  health 0 on the server entity when it is offline); an entity already dead
  or no longer in the checkpoint is a no-op (`death-replay`,
  `death-replay-noop`, `death-replay-skipped`).

## Permitted transient rollback and storage limitations (for G07)

- **Transient rollback (allowed, contract §3):** everything simulated since
  the recovered generation — NPC positions and health between checkpoints,
  items on the ground, the weather effect, the players' own positions —
  returns to the generation; acknowledged ledger values, deaths and respawns
  are re-applied on top. Players rejoin a world up to `checkpoint_seconds`
  old plus the restart time.
- **Storage limitations (not claimed):** power loss and a device that lies
  about flush completion (contract §5, §12); the tests terminate the
  process only. Retention keeps one previous generation. Publication runs on
  the simulation thread (20–620 ms per generation).
- **Not covered here:** inventory, quests and rewards have no records or
  adapters yet (Stage 8: their crash tests come with their adapters); actor
  2's script state is not persisted (L32); deaths of non-ALife objects are
  not records (there are none that matter).
