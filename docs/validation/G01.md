# G01 — Completed for development with user-approved scope reduction

Accepted 2026-10-17. This gate permits Stage 2 headless foundation work using
the [frozen tested baseline](../accepted-baseline.json). It is a bounded
development compatibility gate, not full-campaign or release certification.

## Evidence

- [S01-T01](S01-T01.md): pinned source/toolchain candidate.
- [S01-T02](S01-T02.md): independent content copy and isolated paths.
- [S01-T03](S01-T03.md): two clean builds passed with zero errors at the pinned
  revision; independent user rebuild also passed and its outputs match the
  tested EXE/PDB. Rebuilds differ in timestamp, embedded date, path and binary
  sections; bit-for-bit identity is not claimed.
- [S01-T04](S01-T04.md): user observed New Game rendering/HUD, inventory,
  save/reload with health/ammo/time, dialogue, combat, time persistence and
  level travel. Runtime log and saves are preserved.
- [S01-T05](S01-T05.md): exact executable/content/configuration identities and
  source ownership frozen. Sixty-seven copied archives and 161 overlay assets
  were hash-verified in the tested runtime.

## Explicit user decision and limits

On 2026-10-17, the user stated that completed-quest/reward verification and
the copied original-client comparison were too much for this gate and asked to
proceed based on observed working gameplay. These two requirements from the
original G01/S01-T04 acceptance text are waived **for entry to Stage 2**. The
first quest attempt was failed and remained equipped after reload; it provides
no completed-quest or reward evidence. The original-client comparison has not
run. Neither check is represented as passed. These gaps remain named risks for
later campaign and release validation, or earlier if a related failure appears.

No unexplained startup, asset or critical Lua failure was found in the preserved
test logs after packaging repair. User-observed checks lack numeric before/after
state captures, so the gate rests on practical smoke evidence. Stage 2 must
preserve campaign services and cannot use this scoped acceptance as proof of
shared quest correctness.
