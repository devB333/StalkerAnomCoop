# S05-T01 — Integrate matched client and dedicated roles

Recorded 2026-10-20 UTC. **Status: Completed (2026-10-20).** Source
`builds/build_1/engine-work` at `c57fe5b9` with patches 0001–0027; citations
relative to `src/`. Design: [co-op session integration](../coop-session.md).

## Question

Plan.md S05-T01: route external clients through the adapter and keep the
backend-owned native simulation; no client authority over shared AI, ALife
or campaign mutations, while rendering, input and local presentation stay;
safe isolated launch profiles. **Acceptance:** all three matched executables
start and connect; only the server advances canonical shared gameplay.
**Validation:** process logs, deliberate client outcome injection, the
server running without either client.

## Decision: how the engine links `protocol/`

Static libraries built by `tools/Build-Protocol.ps1` (Stage 1 compiler, `/MD`,
C++17, `/W4 /WX`), linked through `src/Coop.props` (imported by
`Common.props`), with `GameNetworkingSockets.dll` delay-loaded. The engine
compiles without C++ exceptions and with its own PCH and warning set;
linking the tested libraries keeps the shipped objects identical to the ones
the protocol tests run. Details and the rejected alternative:
[coop-session.md](../coop-session.md#linking-the-protocol-into-the-engine-decision-s05-t01).

### Defects found and fixed on the way

- **Profile paths:** `FS.exist` only knows registered files; profiles, stop
  files and keys are absolute Win32 paths (coop-1). The engine's ini reader
  drops spaces in values, so the served save is copied as `coop-campaign`
  (coop-2).
- **Content digest:** the server's scripts rewrite `configs\axr_options.ltx`
  (MCM version stamp) before the server hashed (coop-5); the locator
  registers `scripts\.vscode\*` early and drops it on a later rescan (coop-6).
  Both are excluded; the server now hashes before its scripts run.
- **Repeated actor spawns:** the new actor takes ~0.3–0.7 s to come online;
  the per-tick check spawned another meanwhile (100 actors, coop-7). A pending
  spawn is now tracked.
- **New-game population:** spawning an actor ran `se_actor:on_register` →
  `SIMBOARD:fill_start_position()` (the installed script populates every
  smart terrain with its starting squads unless `start_position_filled` is
  set), adding ~2,700 objects (coop-8). The host now sets the Lua field on the
  new entity before ALife registers it: coop-9 adds 2 objects (the actor and
  its supply).

## Limits

- One Windows host, loopback, two clients sitting in the main menu: no
  world on the clients yet (S05-T02). No LAN/internet test (S11-T01).
- The session layer still reports `server_tick=0` in the Welcome (it has no
  tick source); clients do not use it yet.
- After a refused local start the main menu stays hidden until the client
  quits (cosmetic; the start never happens).
- `inject` covers the protocol surface a client has: no message type carries
  a native event or outcome, so the engine's state-import paths (S03-T02
  policy) are unreachable from the network by construction.
- Liveness defaults unchanged (1/5/15 s); a client blocked for longer than
  15 s (a level load, S05-T02) would time out.
- The G01 waivers and the G02–G04 carried limits are unchanged.
