# S02-T05d — Renderer-free level load, spawn and first tick

Recorded 2026-10-18 UTC. **Completed.** The campaign server runs the native
client loading stages for the fixture save with no graphics device, window,
input or sound device: it connects the in-process client to the server, loads
the level geometry (CFORM), creates the physics world, constructs the
single-player client game state and the level script process, and queues the
server's spawn messages. The first 50 server ticks then spawn every server
entity client-side, including the saved actor, update the objects and step the
physics world, and the process tears down cleanly (smoke-52, exit 0).

This is a renderer-free load and first-tick result, not gameplay: no hit, AI
decision, ALife offline switch, task or save has been checked (S02-T03d,
S02-T04b/c, S02-T06). Parent S02-T05 stays In Progress for S02-T05c.

## Problem (native source)

With no device, no HUD and no UI core, the client stages and the first frame
crash at these points (traced from source, then confirmed at runtime where noted):

1. `IGame_Level::Load` creates the HUD manager (`CHitMarker` and `CHUDTarget`
   shaders) and calls `Render->level_Load`, which is entirely presentation:
   shaders, sectors, lights, details and occlusion (`xrEngine/IGame_Level.cpp:124-129`).
   It also captures input (`IR_Capture`, no `pInput`).
2. `net_start_client5` uploads deferred textures through `Device.m_pRender`
   (`xrGame/Level_network_start_client.cpp:220-229`); `net_start_client6` loads
   the HUD and precaches (`Device.PreCache` reads `m_pRender->GetForceGPU_REF()`).
3. `Load_GameSpecific_After` marks the HUD renderable (`xrGame/Level_load.cpp:193`).
4. `IGame_Level::OnFrame` updates the HUD every frame (`xrEngine/IGame_Level.cpp:195`).
5. **Spawn antifreeze.** With `spawn_antifreeze` on and `g_bootComplete` set,
   `ProcessGameEvents` hands `M_SPAWN` events to the prefetch thread
   (`xrGame/Level.cpp:748-845`). The campaign server starts no prefetch thread
   (S02-T05b), so the spawns would never be processed.
6. **Map spots.** `CActor::net_Spawn` adds two map locations; each creates
   `CMapSpot` UI widgets through `CUIXmlInit::InitStatic` and `UI()`, which needs
   the UI core (`xrGame/map_location.cpp:128-275`, `map_spot.cpp:35-40`).
7. **Found at runtime (smoke-48):** `CActor::load` reads the PDA task-window
   filter flags from `HUD().GetGameUI()->GetPdaMenu().pUITaskWnd`
   (`xrGame/Actor_Network.cpp:1394`); `CActor::save` writes them from there.
8. Reachable in the actor's first ticks (traced after smoke-48): the HUD camera
   pick in `CActor::shedule_Update` (`Actor.cpp:2012`), `HUD().net_Relcase` on
   object release (`Actor_Network.cpp:803`), grenade HUD marks
   (`Actor_Feel.cpp:390-396`), the environment-zone HUD state update
   (`Actor.cpp:1405`), and the hud item aim modifiers and pick
   (`HudItem.cpp:1010-1182`), plus two Lua bindings (`level_script.cpp:2083, 2209`).
9. **View entity.** Native spawn makes the saved actor the control and view
   entity (`xrGame/Level_network_spawn.cpp:118-130`). **Found at runtime
   (smoke-50):** with no view entity, the first spawned stalker makes itself
   the current entity (`xrGame/ai/stalker/ai_stalker.cpp:739-740`, a native
   fallback), after which `CCustomZone::UpdateWorkload` dereferences the null
   control entity (`xrGame/CustomZone.cpp:558-560`; confirmed by disassembling
   the fault address: the code tests the current entity, then reads the control
   entity). `CCustomZone::shedule_Update` also reads the control entity's
   position for its fast-mode distance (`CustomZone.cpp:647`).
10. **Found at runtime (smoke-49):** `CFlashlight::net_Spawn` sets a light
    texture; `light::set_texture` creates the projective and volumetric
    shaders through the null render target
    (`Layers/xrRender/light.cpp:65-104`).

## Decisions

- **No view, control or current entity.** The campaign server has no local
  input and no camera, so `g_sv_Spawn` adopts no control or view entity. The
  saved actor still spawns as a real, enabled, local object with its native
  spawn flags, and `g_actor` is set natively by `CActor::net_Spawn` because the
  server marks the saved actor `M_SPAWN_OBJECT_ASPLAYER`
  (`xrServer_perform_sls_default.cpp:69`). `g_actor`/`Actor()` single-actor
  assumptions and the actor's first-eye camera (`HUDview`) are Stage 3 (G03)
  items, recorded here, not changed.
- **Map locations without spots.** Locations keep their data (hint, flags, ttl,
  border names, owner object) so tasks and scripts can link them; no spot
  widget is created. Spot updates run only from UI map windows.
- **PDA task filters.** The actor now holds the four filter flags it saves;
  with a HUD they are mirrored to the task window as before, so the save format
  and client behaviour are unchanged.
- **Spawn antifreeze** is bypassed only for the campaign server, which has no
  prefetch thread.

## Change

Patch `0010-campaign-level-load.patch`
(SHA-256 `83a288b799ba51e4dd23119cb0221b2e50cc437361312b68c8fb5715cb688804`).
The series reconstructs all 59 changed files byte for byte in
`builds/stage2/patch-check-11b` (`builds/logs/patch-reconstruction-11.json`).

**Engine guards:** `IGame_Level::Load` skips the HUD and `Render->level_Load`
for the campaign server, captures input only when `pInput` exists;
`IGame_Level::OnFrame` null-guards the HUD; `CRenderDevice::PreCache` treats a
missing render device like the dedicated server (nothing to precache).

**Game module:** `net_start_client5` uploads textures only with a render
device; `net_start_client6` and `Load_GameSpecific_After` null-guard the HUD;
`ProcessGameEvents` keeps spawns inline for the campaign server; `g_sv_Spawn`
adopts no entity for the campaign server; `CMapLocation::LoadSpot` creates no
spot widgets for the campaign server; `CActor` stores its PDA task filters;
HUD-pick users in `CActor`, `CHudItem` and the Lua bindings null-guard the HUD.

**Campaign start (`xrGame/CampaignServerStart.cpp`):**
`xrCampaignLevel_PumpClientStages` runs the remaining loading events with a
deadline; `xrCampaignLevel_ReportLoaded` logs and checks the level context;
`xrCampaignLevel_ReportTicks` logs and checks what the first ticks produced.
The smoke driver runs both after the server stages, then `-campaign-ticks`
(default 50) server ticks through the campaign clock. Stages:
`campaign-level-loaded`, `campaign-ticked`. `Run-Stage2Smoke.ps1` expects exit 0
for GameState; a GameState pass is this task's result, not G02.

## Limits

- `level.som` is absent from this level's content (`FS.exist` on `$level$`
  returned nothing); the native path handles the absence
  (`set_geometry_som(nullptr)`). Hearing occlusion for `k00_marsh` therefore
  has no SOM, as in the client.
- Sound stays the interim `-nosound` manager (S02-T05c).
- **NPC sound themes report missing voice files.** `sound_theme.init_npc_sound`
  logged 176 `Couldnt find sounds <path> with prefix characters_voice\…` errors
  while NPCs spawned (smoke-49/50). The accepted client's log has none. Both
  runs mount the same 67 archives (51,012 vs 51,614 cached files). The Lua
  check lives in archive-only scripts and has not been read yet; the cause
  (the `-nosound` manager, or a lookup difference) is open and belongs to
  S02-T05c.
