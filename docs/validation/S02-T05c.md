# S02-T05c — CPU sound events for AI hearing and CPU particle definitions

Recorded 2026-10-18 UTC. **Completed.** Particle definitions have loaded on
the CPU since S02-T05b (1,602 effects, 623 groups; patch 0009). This part
replaces the interim `-nosound` stand-in with the engine's own sound core
running on the CPU with no audio device and no listener (B18): sounds get real
handles and feedback, the native emitter state machine propagates AI sound
events, the level registers hearers and the NPCs' `feel_sound_new` runs. The
GameState smoke (smoke-60) **passed** with the new stage
`campaign-hearing-passed`, the normal client from the same source
(client-18, capture-07) passed the same fixture, and the comparison matches:
the walked stalker's footsteps from the material pairs reach the same hearers
with the same AI range and volume on both sides.

## What the sound pipeline does (source, pinned `c57fe5b9`)

- **Manager selection.** `CSound_manager_interface::_create`
  (`xrSound/sound.cpp:9-28`) always creates the OpenAL core; `-nosound` only
  clears `bPresent`, after which `create`, `play*` and `clone` return early
  (`SoundRender_Core.cpp:294-371`), so no `ref_sound` has a handle or
  feedback. `CSoundRender_CoreA::_initialize` opens the OpenAL device and
  pre-creates the mixing targets (`SoundRender_CoreA.cpp:468-540`).
- **Sources are CPU data.** `CSoundRender_Source::load` reads the ogg header
  and its comment for base volume, min/max distance, max AI distance and the
  game type (`SoundRender_Source_loader.cpp:64-155, 160-182`); `ref_sound`
  creation with `sg_SourceType` takes the game type from there
  (`SoundRender_Core.cpp:_create_data`).
- **Emitters and AI events.** `i_play` creates an emitter
  (`SoundRender_Core_Processor.cpp:11-20`); its state machine
  (`SoundRender_Emitter_FSM.cpp`) starts, simulates when no target is
  available (`i_allow_play`, `SoundRender_Core_StartStop.cpp:63-72`, false
  with no targets) and stops at `fTimeToStop`; while not stopped it calls
  `Event_Propagade` every `s_f_def_event_pulse` (0.5 s), which pushes
  `(owner_data, range)` with `range = min(max_ai_distance, max_ai_distance ×
  volume)` when the sound has a game type and an object
  (`SoundRender_Emitter.cpp:76-91`). `update_events` hands them to the
  level's handler (`SoundRender_Core_Processor.cpp:167-177`).
- **Hearing.** `IGame_Level::SoundEvent_Register`
  (`xrEngine/IGame_Level.cpp:265-331`): spatial query of
  `STYPE_REACTTOSOUND` objects within the range, power `(1 − d / max_ai) ×
  volume × occlusion` with `get_occlusion_to` (hearer to source through the
  SOM, `SoundRender_Core_Processor.cpp:get_occlusion_to`), queued delegates;
  `SoundEvent_Dispatch` (`IGame_Level.cpp:333-352`, from
  `CApplication::OnFrame`) calls `feel_sound_new`. 2D sounds are placed at the
  listener (`Register`) and the camera (`Dispatch`). `CCustomMonster`
  forwards to `CSoundMemoryManager::feel_sound_new`
  (`CustomMonster.cpp:975-988`, `sound_memory_manager.cpp:128-212`), which
  fires `sound_callback`, scales by sound type and stores sounds from
  non-friends it does not see.
- **Listener uses.** `update_culling`/`priority` (listener distance, only
  for target assignment), `get_occlusion` (listener to source, playback) and
  the speed-of-sound start delay (`SoundRender_Emitter_FSM.cpp:53-101`, delay
  from the listener distance, also delaying AI propagation) are the only
  listener-dependent paths; hearing itself is hearer-to-source.
- **Camera gates on producers.** Footsteps: `CStepManager::update` plays a
  step sound only within `g_step_sound_distance` (50 m) of
  `Device.vCameraPosition` (`xrGame/step_manager.cpp:162-223`), from the
  material pair's `StepSounds` with the object as owner
  (`play_no_feedback(object, …)`, `step_manager.cpp:337-366`). Impacts:
  `TContactShotMark` plays collide sounds only within `SOUND_EFFECT_DIST`
  (70 m) of the camera (`xrGame/physics_game.cpp:271-313`); object-vs-static
  impacts play with no owner (no AI event), object-vs-passable through
  `CPHSoundPlayer` with the object (`PHSoundPlayer.cpp:13-29`). Voices:
  `CScriptSound` creates the sound when the file exists
  (`script_sound.cpp:48-60`).
- **Why the server aborted 1,002 sound themes under `-nosound`.**
  `sound_theme.script:125` (read from `db/configs/scripts.db0` with
  `tools/xray-db-extract.py`) aborts with `Couldnt find sounds …` when
  `getFS():exist` found the file but `npc:add_sound` returned 0: the engine
  sound player registered no sounds because `create` returned early.
- **Material pairs on the server** have kept only the media names since
  S02-T03a (`GameMtlLib_Engine.cpp`, `SGameMtlPair::Load`), so `StepSounds`
  and `CollideSounds` were empty and no footstep or impact could be produced.

## Change (patch 0014)

Patch `0014-cpu-sound-events.patch` (SHA-256

See `patches/engine/README.md` for the summary. In detail:

- **`xrSound/SoundRender_CoreCPU.{h,cpp}`**, selected by `-snd_cpu` in
  `sound.cpp`: `_initialize` loads the environment library, sets `bPresent`
  and `bReady`, creates a 2 MB stream cache (the client's is 512 MB; nothing
  is decoded without targets) and no targets; `listener_position()` is a zero
  vector returned only where the interface needs a reference,
  `has_listener()` is false, `get_occlusion` returns 1 (no listener to occlude
  from), `update_events` drops 2D events (counted) and dispatches the rest.
  The base `update` is unchanged: emitters update, targets and EFX loops are
  empty (`m_is_supported` is now initialised false in the base constructor).
  The COM audio-endpoint notification client is deleted in the CPU core and
  its callbacks guard a null `SoundRenderA`.
- **`Sound.h`**: `CSound_stats::_started`, `_events_total`,
  `_events_2d_skipped`; `CSound_manager_interface::has_listener()`.
  `SoundRender_Emitter_FSM.cpp` skips the speed-of-sound start delay when the
  core has no listener.
- **`xrEngine/IGame_Level.{h,cpp}`**: `snd_Stats` (registered, delegates,
  dispatched) and `snd_Trace` (per registered event: file, game type, source
  id/name, position, range, max AI distance, volume, hearers, max power,
  nearest hearer), filled only while a fixture sets the pointer.
- **`xrEngine/xr_object.{h,cpp}`**: `activity_range_distance(position)` —
  the nearest anchor while the policy is enabled, the camera otherwise — used
  by `step_manager.cpp:168` and `physics_game.cpp:272`.
- **`xrEngine/GameMtlLib*.{h,cpp}`**: the single media switch becomes
  `SetPairSounds`/`SetPairMarks`; `StartCampaignMaterials` (`x_ray.cpp`)
  creates sounds when a sound manager exists and no wallmarks, and expects
  `created_sounds != 0`, `created_marks == 0`.
- **`xrEngine/x_ray.cpp`**: `StartCampaignSound` requires `-snd_cpu` and a
  ready core with no listener; the GameState smoke runs the hearing fixture
  around the activity fixture (stage `campaign-hearing-passed`, exit 16).
  `CampaignServerClock::Pause/Resume` pause and resume emitters.
- **`xrGame/sound_memory_manager.{h,cpp}`**: `s_feel_calls` and
  `feel_count()` counters.
- **`xrGame/CampaignHearingCapture.{h,cpp}`** (rows documented in the
  header): `meta` (core, listener, policy, gates, SOM/env presence, the
  stalker, hearers within 50 m, begin counters), `tick` (live emitters,
  rendered, cumulative started/events/2D-skipped/registered/delegates/
  dispatched/feel calls, the stalker's own feel count and remembered sounds),
  `event` (one per registered AI sound event) and `end` (deltas and the pass
  flag). Pass rule: a sound core is present, at least one emitter started, at
  least one event reached the level and a hearer, at least one
  `feel_sound_new` call, and the walked stalker produced at least one event
  while walking; all values finite. Client flag `-s02-hearing-capture`
  (runs the activity fixture too). `Run-Stage2Smoke.ps1` passes `-snd_cpu`,
  expects the stage and copies `server-hearing.csv`;
  `Run-ClientCollisionCapture.ps1 -Capture hearing`;
  `tools/compare-hearing-capture.py`.

## Findings

- **`g_bLoaded` gates hearing.** `IGame_Level::SoundEvent_Register` drops
  every event until the device has processed a frame; the campaign frame
  driver now sets the flag after its own first `seqFrame` pass. Anything else
  that reads `g_bLoaded` (the benchmark start in `device.cpp:434`) is
  presentation.
- **Hearing changes AI behaviour on the server.** The walked stalker moved
  under its own planner during the observation once sounds existed; the
  activity fixture's walked-fraction rule now measures from the walk command.
- **The actor is a hearer.** `CActor` carries `STYPE_REACTTOSOUND`
  (`Actor.cpp:1275`) and received the stalker's footsteps; its
  `feel_sound_new` feeds Lua callbacks on the client, actor-context work for
  Stage 3.
- **Two 2D AI events were dropped** by the CPU core during the fixture (a
  sound with a game type and an owner played 2D). On the client they would be
  heard at the camera. Which sound it was is not traced (the core drops them
  before the level sees them); record if it matters for a gameplay stimulus.
- **The `-nosound` stand-in silently broke scripts**: 1,002 `sound_theme`
  aborts came from sounds without handles, not missing files. Any future
  "disable" of a presentation service must keep the data path (D2).
- **Speed-of-sound delay.** The client delays an emitter's start, and so its
  AI propagation, by the distance to the listener beyond 50 m
  (`SoundRender_Emitter_FSM.cpp:53-101`); the server applies none. For
  sounds within 50 m of the client's camera both sides propagate immediately.
- Emitter lifetimes run on the sound core's wall timer on both sides; the
  server pauses them with its clock.

## Limits

- **The comparison is not byte-for-byte**: the two sides run different
  frame rates and durations and the stalkers wander differently before the
  walk; the compare tool asserts the parameters, each side's pass rules, the
  server's zero 3D drop and the overlap of the walked stalker's event types,
  and reports the totals.
- **Combat was not reproduced on the server** in this window while the
  client saw a firefight (above); hits and combat are S02-T06.
- **No occlusion on this level** (`level.som` absent), so
  `get_occlusion_to` returned 1 and the occlusion path is only read, not
  exercised; a level with a SOM would exercise it identically on both sides.
- **Impact sounds were not produced** in this fixture window: the physics
  fixture's crate landed before the hearing fixture began, and object-vs-static
  impacts play with no owner (no AI event) natively. The gate change in
  `physics_game.cpp` is covered by the same `activity_range_distance` as the
  footsteps, which were exercised.
- **No weapon fire, no bullet hits, no anomaly sounds** were produced; their
  producers call the same `play*` paths.
- **The CPU core's cost was not measured** against the client beyond the
  live emitter count (36–42).
- Sound sources are loaded lazily on first use, as on the client; the first
  footstep of a material pair opens its ogg headers at that moment.
