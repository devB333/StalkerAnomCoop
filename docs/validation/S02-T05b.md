# S02-T05b — CLevel, xrServer, game_sv_Single and ALife from the fixture save

Recorded 2026-10-18 UTC. **Completed.** The campaign server runs the native
start sequence for the fixture save with no graphics device, window, input or
sound device: it constructs the application object, the level object, the server,
the single-player server game state and the ALife simulator, which loads the save,
chooses the level from the saved actor's graph position and loads that level's AI
graph. It then stops at the planned point, before the client stages that load the
level geometry, and tears everything down through the native shutdown path.

No level geometry, physics world, spawned object, client game state or
simulation tick exists yet; those are S02-T05d. Parent S02-T05 stays In Progress.

## Problem (native source)

With no device, no sound manager and no application object, the native path from
level creation to the server stages crashes at these points (all traced before
the change, then confirmed at runtime where noted):

1. `IGame_Level`'s constructor dumps render-resource usage through
   `Device.m_pRender` (`xrEngine/IGame_Level.cpp:31`); its destructor resets
   post-processing through the render target and clears the sound geometry.
2. `CApplication` is needed for the level list and the `$level$` alias
   (`Level_Scan`, `Level_ID`, `Level_Set`), the loading refcount and `LoadTitle`,
   but its constructor registers the sound processor and its loading path draws a
   loading screen, creates a font and sets a level logo (`xrEngine/x_ray.cpp`).
3. The native idle loop never pumps loading events while the device is not ready
   (`xrEngine/device.cpp:405-409`).
4. `restart_all` calls `MainMenu()->DestroyInternal(true)` on a null menu
   (`xrGame/alife_simulator.cpp:34`); on a never-activated menu the call is a no-op.
5. `CLevel`'s constructor starts the spawn-prefetch thread, which does render
   prefetch and has an unsafe shutdown order (`xrGame/Level.cpp:270-279`, `331-338`).
6. **Found at runtime (smoke-41):** the ALife constructor re-initialises the script
   engine, and an installed script constructs the particle group
   `anomaly2\teleport_out_00` during that auto-load. The particle library is
   empty because it loads inside `CRender::create` (`Layers/xrRenderPC_R4/r4.cpp:537`).
7. **Found at runtime (smoke-42):** the same auto-load constructs `sound_object`s
   (`xrGame/script_sound.cpp:60`) with no sound manager.
8. **Found at runtime (smoke-43):** at shutdown, `CLevel::ProcessGameEvents`
   calls `GameID()` through the client game state, which does not exist when only
   the server stages ran (`xrGame/Level.cpp:940`).
9. `remove_objects` clears static wallmarks through a wallmark engine that exists
   only after a rendered level load; `IGame_Level::net_Stop` releases input.

## Change

Patch `0009-campaign-level-start.patch`
(SHA-256 `17f391f4cd5a64108a1818d56f015213223d57a6a426419a61bf4298744673f0`).

**Game module, new `xrGame/CampaignServerStart.cpp`:**
- `xrCampaignLevel_Start(op_server, op_client)`: the `KERNEL:start` sequence
  without the menu console commands: `PreStart`, `NEW_INSTANCE(CLSID_GAME_LEVEL)`,
  `LoadBegin`, `Start`, `net_Start`, `LoadEnd`.
- `xrCampaignLevel_PumpServerStages(deadline_ms)`: runs the queued loading events
  until three remain (`net_start4` replaces itself with the client stages), with a
  wall deadline. Returns distinct codes for success, timeout and a failed stage.
- `xrCampaignLevel_Report()`: logs the level name, the saved actor and its graph
  position, ALife and server entity counts, graph sizes and game time, and checks
  the actor is on the loaded level.
- `xrCampaignLevel_Stop()`: the `KERNEL:disconnect` sequence: `net_Stop`,
  level deletion, persistent `Disconnect`.

**Engine and renderer guards (presentation-only, no behaviour change with a device):**
`DumpResourcesMemoryUsage`, `CCameraManager::ResetPP` (null target),
`IGame_Level` sound geometry/handler reset and input release, `OnAssetsChanged`,
`CApplication`'s sound processor registration, loading font/render begin, loading
draw, level logo, loading-shader destruction, and `clear_static_wallmarks`.

**Game-module changes:** `restart_all` null-guards the menu; the campaign server
does not start the spawn-prefetch thread; `ProcessGameEvents` null-guards the
client game state; `xrGame.vcxproj` adds the new file.

**Particles (S02-T05c part):** `cpu_models_create` loads the particle library
(`PSLibrary.OnCreate`) after the model pool, in the native order, and
`cpu_models_destroy` unloads it. Per-definition shader creation is skipped like
any other GPU resource. Instancing an effect only uses the CPU particle manager
and guarded shader/geometry creation (`Layers/xrRender/ParticleEffect.cpp:206-255`).

**Sound (interim):** a `sound` service runs first and requires `-nosound` on the
command line; it creates the engine's own sound manager with no device
(`xrSound/sound.cpp:9-27`), so `create` returns early
(`xrSound/SoundRender_Core.cpp:294`) and nothing has feedback. Two fixes make that
mode safe: the OpenAL core now initialises `m_is_supported` (its destructor read
it uninitialised when device setup was skipped), and `ref_sound::set_position`
tolerates missing feedback like the other setters. AI hearing is therefore **not
modelled**; the CPU stimulus layer remains S02-T05c (B18).

**Campaign smoke:** `application` service after the registries (before
`persistent`), `sound` service first; the GameState scope now runs the campaign
start, reports `campaign-level-created`, `campaign-server-ready` and the planned
`level-context-required` (exit 3), then `campaign-stopped`. The clock pauses while
loading. The launcher passes `-nosound`, allows 420 s for GameState, and
`prepare-stage2-smoke.py` copies the fixture save pair into each run's save
directory after checking its hashes against `docs/headless-fixture.json`.

The series reconstructs all 44 changed files in `builds/stage2/patch-check-10b`
(`builds/logs/patch-reconstruction-10.json`).

## Limits

- **Server stages only.** No level geometry, physics world, spawned object, client
  game state or tick. The 1,074 server entities are ALife's online switch result;
  no object was processed client-side, and `M_SPAWN` would be dropped before
  `bReady` anyway.
- **Sound is a stand-in.** The `-nosound` manager makes sound creation succeed
  with no feedback. Nothing is audible to AI. The `-nosound` core also starts a
  COM audio-endpoint notification client (`xrSound/NotificationClient.cpp:17-43`);
  that is native behaviour, not a device.
- **Lua side effects unknown.** `start_game_callback`, the storage-manager Lua
  load and the auto-loaded scripts ran with a real level object but no loaded
  level. Their observable effect so far is the particle, sound and callback
  messages above.
- **View entity deferred.** Native spawn makes the saved actor the view entity
  client-side; that decision belongs to S02-T05d, where spawns are processed.
- **Loading-event pump.** The server pumps `g_loading_events` serially with a
  300 s deadline; the native per-frame engine events are not run during loading
  (natively they aren't either, while loading events are queued).
