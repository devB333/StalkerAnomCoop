Recorded 2026-10-18 UTC. **Status: Completed (2026-10-18).** The actor access
adapters, the inventory of every `Actor()`/`Level().CurrentEntity()` use, the
server message policy and the authority fixtures are patch 0022

## Question

Plan.md S03-T02: keep cameras local without global actor mutations.
Introduce explicit actor/context lookup for core gameplay; retain local-view
access on clients only; restrict the privileged state-import bridge to the
server runtime and enumerate and reject the remote outcome paths.
**Acceptance:** server gameplay can operate without the client view
`Actor()`; remote state imports cannot set health, inventory or world
state. **Validation:** negative role tests; two actor contexts; the server
with no rendering client. **G02 carried input (B21):** inventory and
classify every `Level().CurrentEntity()` / `Actor()` use in `src/xrGame`
(126 / 372 raw sites); resolve `phantom.cpp:86,149,266`, `ai_trader.cpp:99`
and the psy dog aura guard, or keep each behind a recorded guard.

## What the engine does (source)

- `Actor()` returns `g_actor`, the last actor spawned with
  `M_SPAWN_OBJECT_LOCAL` and `M_SPAWN_OBJECT_ASPLAYER`
  (`xrGame/Actor_Network.cpp:58-67,530-531`); the server forces every actor
  local (`Actor_Network.cpp:525-528`), so with two actors the global is
  whichever spawned last.
- `Level().CurrentEntity()` / `CurrentViewEntity()` are the objects the
  local input and camera control (`xrEngine/IGame_Level.h:147-150`,
  `IGame_Level.cpp:259-278`); the client adopts the actor as its entity at
  spawn (`Level_network_spawn.cpp:148-163`), the campaign server adopts
  none (S02-T05d).
- The server's private state bridge is the direct client (`ClientID 1`,
  `xrServer::create_direct_client`, `xrServer.cpp:1043-1052`), `bLocal` and
  `SV_Client` (`xrServer_Connect.cpp:118-123`, `xrServer.cpp:890-921`). Only
  `Process_update` and `Process_save` checked it, as `R_ASSERT(bLocal)`
  (`xrServer_process_update.cpp:14,66`); `M_SPAWN` was gated on `bLocal`;
  every other message in `xrServer::OnMessage` (`xrServer.cpp:471-770`) and
  every game event in `Process_event` (`xrServer_process_event.cpp:13-...`)
  was dispatched for any sender. `GE_HIT` becomes `GAME_EVENT_ON_HIT`
  (`xrServer_process_event.cpp:145-155`); `GE_DESTROY` destroys an entity
  (`xrServer_process_event_destroy.cpp`), `GE_OWNERSHIP_TAKE` moves an item
  (`xrServer_process_event_ownership.cpp`), `GE_INFO_TRANSFER` is broadcast
  to every client, `GE_CHANGE_VISUAL` and `GE_INSTALL_UPGRADE` mutate the
  server entity, `M_UPDATE` imports health and position through
  `UPDATE_Read` (`xrServerEntities/xrServer_Objects_ALife_Monsters.cpp:1137-1154`).

## Acceptance

- **Server gameplay can operate without the client view `Actor()`.** The
  GameState smoke ran its 61 stages (load, ticks, collision, physics,
  activity, hearing, combat, quest, two checkpoint round-trips) with
  `local_view_actor()` null throughout (280,068 calls), the view entities
  null, and the gameplay sites on explicit participant lookups; the only
  `Actor()` callers left on the server are presentation, script bindings
  and the recorded abilities, and `Actor()` itself returns null and counts
  rather than choosing once two participant actors exist (unit fixture;
  the two-actor run is S03-T03).
- **Remote state imports cannot set health, inventory or world state.** A
  forged health update, a save-packet, a spawn, every world control, and
  hit/destroy/ownership/info/visual events from a remote or unknown sender
  were refused before parsing with the state unchanged, while the same
  messages from the bridge were accepted (the health import observed live
  and restored).
- **Negative role tests** (unit and level): a client intent never resolves
  another participant's actor, the bridge session is never a participant,
  a client-role registry authorizes nothing. **Two actor contexts** were
  exercised with one real actor and one actor-less participant on the
  loaded level, and with two actors in the unit fixture.
- **B21 (G02 carried input):** the inventory classifies all 126 + 372 sites
  ([actor-access-inventory.md](../actor-access-inventory.md)); the phantom
  and trader dereferences are participant lookups with recorded no-actor
  behaviour; the psy dog aura is the viewer's (null on the server by rule).

## Limits

- One real actor: the ambiguity refusal (`Actor()` null with two
  participant actors) is observed only in the unit fixture; S03-T03's
  second native actor is the level test, and the audit table will show
  which presentation/script/ability callers dereference `Actor()` without
  a null check once it refuses.
- The player-bound monster abilities (104 sites in 12 files) and the Lua
  `level.*` bindings (38 sites) still go through the compatibility
  accessor; they target the sole participant actor. S03-T04 records the
  abilities, S10-T02 owns their per-participant form, S03-T05 the script
  context contract.
- `sole_participant_actor` sites (tasks, map-location callbacks, script
  holders, autosave, inventory box, dialogue without an actor speaker)
  refuse with two actors; their contexts come with S03-T05/S08/Stage 7.
- Script post-process effectors and controllers are dropped on the server
  (no viewer) until S03-T05 routes presentation to the client.
- The client's `Role::Client` registry knows only its own actor; Stage 4
  fills the roster. A remote client's `M_CL_INPUT`/`M_CL_UPDATE` pass the
  policy as intents but nothing consumes them yet (Stage 4/6).
- The remote client in the level test is a server-side record with no
  socket; the network path itself (DirectPlay/GNS) is Stage 4.
- The dbghelp symbols are the nearest public symbol: two callers
  (`CKinematics::CLBone`, `CWeapon::OnZoomOut`) name the neighbouring
  function of inlined IK/zoom code; offsets are exact.
- The G01 waivers and the G02 carried limits (one level, one save, short
  runs, timing differs, checkpoint without journal) are unchanged.
