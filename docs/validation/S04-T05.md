## Question

**Acceptance** (plan.md S04-T05): disconnect detected; a stale session cannot
keep submitting; reconnect restores the same participant without duplicate
slots. **Actions:** measured, configurable heartbeats, a bounded timeout
policy, token rotation and same-process resume; define the actor's behaviour
while disconnected; durable recovery later. **Validation:** dropped

**Risk:** no cross-restart recovery claim; timeout defaults are provisional.

## Design

- **Heartbeat.** The client sends a reliable Heartbeat every
  `heartbeat_interval_ms` and the server echoes it at once.
  - Reliable, because GNS starts its dead-peer clock only on traffic that
    expects an acknowledgement (S04-T01 finding 1).
  - The echo gives the client an application round-trip time and gives the
    server traffic the transport must acknowledge.
- **Timers.** Each side keeps its own last-heard time; any message counts.
  Suspect after `suspect_after_ms`, closed after `timeout_ms` (code 1105,
  `Left{Timeout}` / client `Ended(Timeout)`). The transport's timeout is set
  1 s above (`session::transport_config(liveness)`), so the session layer
  decides. Defaults 1 s / 5 s / 15 s follow `network-protocol.md`'s
  provisional policy; the tests use 0.2 s / 1 s / 2.5 s.
- **Disconnected player.** The slot, player and party stay bound (the
  participant model's "detached"), so a third player cannot take the slot.
  The actor stays in the world, gets no input and stays vulnerable, and its
  area stays online (S03-T04). The simulation applies that from S05-T01.
  Optional `release_after_ms` frees the slot later (default never).
- **Resume.**
  - The key proof is always required.
  - A Hello may also carry the last session id, its latest token and the
    client's cursors. If SHA-256(token) matches the stored hash (constant-time)
    within `resume_window_ms`, the session id continues, and the game gets
    `Joined{resumed, last_event, last_snapshot}` to continue from those
    cursors. Otherwise the player gets a fresh session.
  - Every Welcome rotates the token; the server keeps only its hash.
- **Stale connections.** A newer authenticated connection of the same player
  closes the older one (1103) and removes it before the Welcome, so whatever
  it still has in flight is discarded by the transport. Every message event
  carries its connection's `join_serial`.
- **Shutdown.** `Server::shutdown` ends every session (`Left{Shutdown}`) and
  shuts the transport down (clients see `PeerShutdown`, 1004). Everything is
  in memory: a new server process gives a resuming client a fresh session.

## Tests (pt-9)

Each runs on the fake (virtual time) and on GNS over loopback (real time).
Settings: heartbeat 200 ms, suspect 1,000 ms, timeout 2,500 ms.

| dead-client-detected | fake: the client's process dies; GNS: 100% loss both ways | server Suspect after 912 / 904 ms and `Left{Timeout}` after 2,412 / 2,405 ms (silence began up to one heartbeat earlier); the slot stays the player's (`connected=false`); GNS client `Ended(Timeout)` after 2,407 ms |
| dead-server-detected | fake: the server's process dies; GNS: 100% loss | client Suspect, then `Ended(Timeout, 1105)` after 2,501 / 2,502 ms |

## Acceptance against the plan

- **Disconnect detected:** dead-client-detected and dead-server-detected,
  both ways, within the configured timeout (±0.2 s, one heartbeat).
- **A stale session cannot keep submitting:** stale-connection-cannot-submit
  (0 accepted after the switch, in-flight dropped), resume-same-session (an
  old token resumes nothing).
- **Reconnect restores the same participant without duplicate slots:**
  resume-same-session, repeated-reconnect (15 cycles, one slot per player).
- **Dropped connection, delayed old messages, repeated reconnect, server
  shutdown:** the scenarios of the same names.

## Limits

- Defaults (1 s / 5 s / 15 s, 10-minute resume window, no auto-release) are
  provisional. Only the short test values were measured, on loopback and the
  fake. Real networks with loss and jitter are S11-T01.
- No recovery across a server restart (Stage 7); the tests show it is not
  claimed.
- The detached actor's behaviour is specified, not yet applied. The session
  layer is not inside the engine until S05-T01.
- Resume continues the session identity and reports cursors. Replaying
  missed events and snapshots from them is S05-T02/S07-T05.
- Same limits as S04-T02..T04: one host, loopback, no sanitizer, and the
  man-in-the-middle limit of the handshake.
