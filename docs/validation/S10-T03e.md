## What was built

- **The sweep fixture** (`CoopServerHost.cpp` "S10-T03e", `sweep_fixtures`,
  profile key `sweep_party = <seconds>`): once both players are in the world
  and nothing is executing, the server reads every online-or-offline
  `CLevelChanger` of the spawn data (its level, its destination level: the
  **graph**, logged as `fixture-sweep edge`), then repeatedly picks the
  nearest untravelled passage (breadth-first over the graph, through
  changers not refused) and sends a travel request on player 1's behalf
  through that changer, answered *yes* on player 2's behalf
  (`take_travel_request` / `take_travel_answer`, the S09 consent path). The
  S09 executor carries the party out; the passage is **ok** when the server
  reloaded on the destination level and both clients rejoined there
  (`fixture-sweep passage … result=ok`). A trip that only moves the party
  toward an untravelled passage is logged `sweeping=0`. A changer refused
  with 24 (disabled by the story) is not tried again; other refusals are
  retried.
- **Test-only bypasses** (T03e-1): the sweep's own requests skip the
  "at the changer" check (25) and the combat check (27)
  (`sweep_bypass`, set only around the fixture's two calls), and the
  fixture turns on god mode for the party, so an arrival among monsters is
  not a death (refused 3 in sweep-1) and a monster's attention is not a
  refusal (27 in sweep-2). Nothing changes for a player's request.
- **Fixes found by the sweep** (patch 0080):
  - **B11** (psy dog phantom): a phantom whose spawn failed on a client was
    destroyed before it joined a squad, and the cleanup crashed both clients
    in `CMonsterSquadManager::remove_member`
    (`ai_monster_squad_manager.cpp`); the lookup is now bounds-checked. The
    refusal (`CustomMonster.cpp`, "refused by the entity") now logs
    `alife=0|1`, whether the client's ALife held the object. The refusal
    did not recur in sweep-4, -6 or -7, so its cause stays open.
  - **B15** (identity check after a travel reload): the S03-T01 check
    (`CampaignIdentityFixture.cpp`) counted an object ALife had just
    released (its `GE_DESTROY` not yet processed) as an online object with
    no server entity and stopped the server. It now skips objects queued
    for destroy (`getDestroy()`), names up to 5 others, and
    `x_ray.cpp` runs it again after 10 more ticks, up to 3 times, before
    stopping (a real mismatch still stops). The stop's `log_status` no
    longer reads `Level()` once the level is gone (it crashed in sweep-4).
- **Tools**: `prepare-coop-session.py --sweep c1,c2 [--sweep-start 20]
  --client-exit-after <s>`; `tools/compare-coop-sweep.py` (graph, coverage,
  travels, clients; `--tsv` writes the per-passage table).

## Limits found here

- The sweep travels from wherever the party stands (the changer and
  combat checks are skipped for its requests, T03e-1) with god mode on; the
  checks themselves are S09's and were tested there (tv-1…tv-26).
- Story-disabled changers: none refused in sweep-7, because a fresh fixture
  save has every changer enabled; a story state that disables one is not
  swept.
- The phantom's spawn refusal (B11) did not recur, so its cause is still
  unknown; the client now logs `alife=` when it does.
- After each reload the server's clock falls up to 1.6 s behind for its
  first frames (the Lua garbage collection after the load) and drops that
  simulation time; this is the clock's design (S05) and also seen in
  S10-T03c/d runs.
