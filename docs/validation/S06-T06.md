## What changed

**Engine (patch 0036)** — `CoopServerHost.cpp`, `CoopClientLink.cpp`,
`Layers/xrRenderPC_R4/r4.cpp`; **protocol** — `session/server.{h,cpp}`, test:
- **Server crash on blood and bullet marks fixed.** In cenc-5 the campaign
  server crashed (`0xC0000005`, minidump in the run's `server/`): a stalker
  took a hit, `CEntityAlive::BloodyWallmarks` → `PlaceBloodWallmark`
  (`entity_alive.cpp:423-468`) → `CRender::add_StaticWallmark`
  (`r4.cpp:893-898`) → `CWallmarksEngine::AddStaticWallmark`
  (`WallmarksEngine.cpp:326`) on a null `Wallmarks`. The wallmark engine is
  only created by a rendered level load, which the server never does
  (`clear_static_wallmarks` was already guarded for this). Marks farther than
  `wallmark_range_static` (100 m) from the camera are skipped, and the
  server's camera is at the origin: the marsh fights were about 585 m away,
  Cordon's about 250 m. The static and skeleton wallmark entry points now
  return when there is no wallmark engine; this covers blood, bullet,
  physics and script marks. Clients are unchanged (they have the engine).
- **No fixture or program names Fanat (19409).** The boar's spawn point is the
  reachable node 8–12 m from participant 2 farthest from participant 1 and
  from every other living creature within 60 m. The encounter record has no
  Fanat row. The encounter program no longer sprints away from Fanat first.
- **Encounter monster:** Cordon's own `boar_01a_weak` (75 % health,
  fire-wound immunity 0.9 against 0.8). In cenc-1 `boar_normal` killed both
  pistol players and lived.
- **Dead walk at +8 s, forged revive at +11 s** (were +5 s and +8 s): in
  cenc-1 a body still slid 0.28 m down Cordon's slope at +5 s.

- **Join race under loss fixed** (protocol `session/server`, `CoopServerHost.cpp`;
  `proto-build-31`). In cenc-14 (10 % loss, 100 ms each way) player 2's
  client closed during its join with 1003, "message before the session
  started", and sat out the run. Reliable channels are ordered only within
  themselves: the server started the world stream (bulk channel) right after
  the Welcome (control channel); the Welcome was lost and resent, and a chunk
  arrived first. The session server now marks a player confirmed once its
  client has sent anything inside the session (the client sends nothing
  in-session before its Welcome, and it sends a heartbeat on its first update
  after it), and the host starts the world stream only for a confirmed
  player. Snapshots, the world clock and lifecycle events already waited for
  the world stream. New protocol test `session/confirmed-after-client-speaks`
  (fake and GNS); 98/98 pass (pt-29).
- **A reused id with the same section is a new object on the client**
  (`CoopClientLink.cpp`, `apply_spawn`). In csession-3 and csession-4,
  client 1's replica had participant 2's PDA (7606 / 7230) in its set but
  never in its level. The replica's registry comes from a checkpoint that
  also holds every offline object; the server releases offline objects
  without an event and reuses their ids. A spawn whose id the replica already
  had with another section was already replaced ("spawn-replaces", dozens per
  Cordon session), but one with the same section (`device_pda` → the new
  actor's `device_pda`) was taken for the same object coming online. The
  stale object kept its old parent, an offline NPC, so it never came online.
  Such a spawn is now a new object when the server's entity differs from the
  one recorded for that id, or when its parent differs from the stale
  object's. An object coming online keeps both. The marsh sessions never hit
  this; Cordon has many more NPC PDAs coming and going.
- **The boar dies too at the 60 s mark.** `lethal` already killed a living
  participant 2 60 s after the spawn while the boar lived; the boar now takes
  a lethal hit at the same moment (logged `encounter monster-lethal`), so
  every run has an NPC death to present. In cenc-8 the weak boar killed both
  players (two pistol hits landed) and lived.

**Rule changes after seeing data** (all before the final runs, cenc-19…22):
- *Monster `boar_01a_weak`* and *dead walk at +8 s* (cenc-1, above).
- *`dead_inert` on the client uses the client's own actor position from its
  log* (where the dead walk began and ended), not the 10 Hz record. In cenc-3
  a boar beside player 2's body moved its ragdoll 0.93 m on the client (0.08 m
  on the server) while the actor stayed put. The record's figure is still
  reported as `body_drift`. A dead actor's position on the client does not
  follow its ragdoll, so the client half only shows that no input moved the
  actor; the server half (< 0.10 m, no shots) is the authority check.
- *The boar's lethal hit at 60 s* (cenc-8, above).

**Tools:** `prepare-coop-session.py --fixture cordon|marsh` (Cordon is the
default; the pair is hash-checked against `docs/cordon-fixture.json`);
`tools/New-FixtureSave.ps1` (new, above); `docs/cordon-fixture.json` (new).

## Limits

- **The Cordon actor carries slight radiation** from the user's walk; about
  0.3 % health a minute, within every check's tolerance.
- **The boar is forced to die at 60 s** if the players have not killed it;
  its death is the native one, but not a combat outcome. `npc_damage` and
  `player_damage` exclude the fixture's own lethal hits.
- **The client's dead-walk check reads the actor object**, whose position on
  a client does not follow its ragdoll; the server's check is the authority.
- **Replica registry:** offline objects released on the server stay in a
  client's registry until their id is reused (they are not online, so not in
  the level). The client now replaces them on reuse; it does not prune them.
- New-game fixture generation (`tools/New-FixtureSave.ps1`) is kept as a tool,
  but no installed Cordon start suits the tests; the used save is
  user-made.
