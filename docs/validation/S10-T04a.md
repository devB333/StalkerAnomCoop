## What was built

A co-op client's talk window no longer runs the installed dialogs locally
against the replica (L43). The USE key on an NPC sends **talk start**
(ActionIntent 14); the server checks the player's actor, the NPC (a living
inventory owner that talks, not an actor), the talk reach (3 m, as the S08
giver reach) and **one speaker per NPC** (T01-15: an NPC already talking to
the other player refuses with 33), then opens the dialogue in the player's
script context (`campaign::dialogue_open`) and runs the native window's
logic server-side: the NPC's start dialog (`InitOthersStartDialog`), the
topic and phrase lists with the dummy auto-say (`UpdateQuestions`), and a
clicked id as `AskQuestion`/`SayPhrase`, the NPC's reply included
(`CAI_PhraseDialogManager::AnswerPhrase`). Every change goes to the talking
player as **CampaignEvent 14**: 1 open, 3 an answer, 4 a list (in parts),
2 closed with the why. The client's `CUITalkWnd` gets a **remote mode**: it
shows the lists and answers it is sent (translated as the native window
translates them), a click is **talk say** (15) with the clicked id, closing
the window is **talk end** (16); trade and upgrade are off (T04a-4). The
actor and the partner replica take the single-player talking state, so the
window is modal and the actor stands still; on the server a talking actor's
movement and trigger inputs are consumed and dropped (T04a-1,
`inputs_held`). A talk ends with its actor, its NPC, its reach or the
player's connection (`talk_tick`, `on_left`); a new connection or a server
restart closes the client's window (`talk-reset`).

**The party quest through the window.** The installed task dialog's accept
action (`dialogs.npc_give_task`, on the actor's phrase) and the finish
action (`dialogs.npc_set_finished_task_complete`, on the NPC's auto-reply)
are taken over by `campaign::coop_server_dialogue_action` (a hook in
`CDialogScriptHelper::Action`) and run through the S08 party path in the
anchor's context: `quest_accept_phrases(anchor, npc, task)` and the shared
`party_task_accepted` (the task recorded, its instance saved with the
anchor, both players told, the accept durable after a published
generation); `campaign_party_check` + `quest_turnin_phrases(holder, npc)`
and a pending turn-in that `quest_tick` completes (pooled patches, each
player paid for its own, the same goodwill for both). A talk's accept or
turn-in has no action result to answer (waiter operation 0:
`quest-talk-durable`). A non-party task offered through the window is not
given (T04a-3: the player is told as news, the dialogue continues).

## Limits found here

- Either player turns the party task in by talking (talk-9): the ordered
  dialog's `db.actor:get_task` reads the level's task manager, not a
  per-actor registry. Other `db.actor` reads in dialogue preconditions
  (info portions, money, the companion checks) are still the talking
  player's: S10-T04b.
- A non-party task offered through the window is **not given** (T04a-3),
  and the NPC's "accepted" line is still spoken after the refusal (the
  phrase tree has no refusal branch). S10-T05b owns the dynamic task types.
- The dialogue's preconditions and texts run in the talking player's
  context: story info portions are per player until S10-T04b (T01-4).
- The busy hint on the HUD ("*name* is busy talking to the other player.")
  and the window's look are the hands-on check; the fixture's refused starts
  are the driver's (no HUD text). `PlaySnd` plays the dialogue voice lines
  as the native window does; not checked by a run.
- The driver's same-id repeat of a say is evaluated afresh by the server
  (a talk kind is not a stored outcome): 14 `talk-say-refused` lines in
  talk-7 are those repeats (35: the id is no longer in the list). Harmless;
  a player's double click is stopped on the client (`m_remote_waiting`).

## Hands-on check (the user, 2026-10-29, demo-3…demo-5 on campaign-317/318, client-214/215)

Both players were placed beside Sidorovich by the `place_giver` aid (patch
0061; his bunker door has no co-op USE path yet, S10-T04c). Observed:

- **The busy hint works**: "*Sidorovich* is busy talking to the other
  player." on the second player's HUD while the first talks (`talk-busy`
  twice in demo-5).
- **The talk window works** and a task accepted through it is the party's
  on both PDAs (`quest-accepted slot=1 task=esc_m_trader_task_recover_item_on_corpse_wt
  … source=talk`, S10-T05b).
- **Sidorovich is silent.** His dialogue phrases have no voice files in
  this install (`characters_voice\dialogs\` holds none of the `esc_*` /
  `dm_*` phrases: silent in single player too); the voice heard in single
  player is his logic's `xr_sound` greeting and goodbye lines
  (`characters_voice\scenario\trader\…`), which a sound on an NPC did
  not replicate (L05). **Patch 0062** sends a script sound on a living NPC
  or monster to the players as a sound at its position. Not yet heard by
  hand.
- **The party task had no map spot on the clients' PDAs**, and clicking it
  centred nothing: the task list went out at the accept, the installed
  `check_task` set the target a second later, and neither the server's
  resend hash nor the client's update looked at the map location. **Patch
  0062** adds the location and the map object to the hash and the client
  relocates the task (`party-task relocated`). Not yet seen by hand.
- Found on the way: a demo placement spot 1.5 m in front of him is inside
  his desk (the physics ejected the actor when the partner brushed it, the
  contact damage killed it: demo-3/4); the aid uses the talk fixture's spots.
