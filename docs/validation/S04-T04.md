# S04-T04 — Bind authenticated sessions to canonical players

Recorded 2026-10-20 UTC. **Status: Completed (2026-10-20).** No engine change
(no patch). Project code: `protocol/include/coop/session/`,
`protocol/src/session/`, `protocol/tools/coop_keytool.cpp`,
`tests/session/`; codec changes in `protocol/include/coop/proto/messages.h`.
Design and deployment: [sessions and authentication](../session-authentication.md).

## Question

**Acceptance** (plan.md S04-T04): spoofed player ids, a third active client
and incompatible builds cannot enter authority; two legitimate peers receive
distinct identities. **Actions:** initial deployment, authentication and
credential storage; reconnect credentials bound to stable player ids; two
active slots, build/content match, rate limits; no privileged local-client
role for external peers. **Validation:** positive two-peer joins plus
impersonation, replay, excessive requests and mismatch tests. **Risks:** do
not confuse transport encryption with identity; do not log tokens or commit
credentials.

## Result

Accepted, with the man-in-the-middle limit stated below. Final build
**proto-build-11** (0 warnings at `/W4 /WX`). **pt-6**: 43/43 (codec, guard,
fuzz, wire, crypto and session tests). **tr-8**: the transport suite, 51/51.
`coop-keytool` was checked by hand (**keytool-1**).

## Decisions

1. **Per-player ECDSA P-256 keys, server holds public keys only.**
   - Rejected alternative 1: GNS certificates. The open-source library takes
     its root CA key at compile time
     (`steamnetworkingsockets_certstore.cpp:271-317`), so every host would
     rebuild GNS with their own CA.
   - Rejected alternative 2: shared secrets, where the server's list would be
     as sensitive as the keys.
   - Windows BCrypt provides P-256, SHA-256 and the RNG, and DPAPI protects
     the client's key file. Both ship with Windows; BCrypt is already loaded
     by the GNS DLL.
2. **Challenge-response, two new handshake messages.** Hello carries a
   32-byte client nonce (replacing S04-T03's opaque auth blob). AuthChallenge
   carries the server nonce and the campaign id. AuthProof carries the
   signature over a transcript of both nonces, the campaign, the player id,
   build, content and version. v1.0 had no deployed peers, so the change stays
   in v1.0. The S04-T03 report is amended.
3. **A player owns a slot, not a connection.** The slot survives disconnects
   (a third player cannot take it). The same player's new authenticated
   connection replaces a live-looking old one (S04-T01 finding 2). Only the
   server releases a slot, and its generation then moves on.
4. **Rate limits:** per address before the handshake, per connection and
   channel after it. Reliable overflow closes the connection; transient
   overflow drops. Handshakes time out.
5. **Attribution from the binding only.** No message names its acting
   player; `SessionEvent::player` comes from the connection's binding.
6. **Build and content identity** is defined
   ([sessions](../session-authentication.md#build-and-content-identity)).
   Computing it in the engine is S05-T01.

## Acceptance against the plan

- **Spoofed player ids cannot enter:** impersonation-refused,
  replayed-proof-refused, transcript-binds-everything.
- **A third active client cannot enter:** third-player-and-slots. Before the
  session layer, the transport also caps open connections (1001).
- **Incompatible builds cannot enter:** build-mismatch-refused.
- **Two legitimate peers get distinct identities:** two-players-join.
- **Reconnect credentials bound to stable player ids:** the player's key is
  the reconnect credential. A reconnect gets the same slot
  (third-player-and-slots, same-player-replaces-session). In-memory resume
  with the Welcome's token is S04-T05.
- **No privileged local-client role:** decision 5 and the
  `wrong_direction`/order checks (handshake-timeout-and-order,
  `wire/server-only-message-from-client`).
- **Tokens not logged, credentials not committed:**
  no-credentials-in-diagnostics. The key files from tests and keytool-1 live
  under ignored `builds/` paths or are deleted by the tests.

## Limits

- **Active man in the middle (stated, R06).** Over unauthenticated GNS
  encryption, an attacker on the path who relays a live handshake keeps the
  session. Strangers, eavesdroppers, the other player and replays are
  stopped. Upgrade paths are listed in
  [sessions](../session-authentication.md#handshake).
- DPAPI ties a key file to one Windows user on one machine; moving a player
  to another PC means a new key and roster line.
- The roster is read at start-up; there is no revocation while running.
  Changes take effect on the next server start (or `release`).
- Build/content digests are fixed values in the tests (S05-T01 computes
  them).
- Address limits use the address GNS reports; behind NAT several players can
  share one. Only one host and loopback were tested.
- Liveness heartbeats, timeout policy for a silent session and in-memory
  resume with token rotation are S04-T05.
