## Assessment

Multiple player entities are structurally plausible, supported by retained MP classes and per-instance health/inventory. A functioning cooperative campaign requires substantial changes to actor context, simulation input, ALife activation, task ownership and special AI. Simply instantiating another `CActor` is insufficient. This is a source-based feasibility inference, not observed gameplay.

For the first supported scope, keep both players on one active level with a server-controlled party transition barrier. Independent levels remain unresolved: investigate world/physics/AI level globals and either introduce multiple simulation contexts or coordinate separate simulation workers. Offline ALife across the global game graph is not evidence of two concurrently loaded online levels.

## Focused next checks and proposed verification

1. Build inclusion of `CActorMP` and `CSE_ActorMP` and object factory mode selection; instantiate two actors in an isolated copied runtime and assert distinct IDs, condition/inventory pointers and correct remote rendering.
2. Trace `CActor::shedule_Update`, `UpdateCL`, movement physics and hit processing to separate per-player authoritative inputs from HUD/camera work. Verify two input streams affect only their respective actors.
3. Replace global actor access by explicit context in a narrowly scoped experimental branch only after implementation authorization. Regression-test existing SP behavior; keep changes revertible as isolated commits.
4. Examine installed campaign Lua actor binding, task/info callbacks, dialogue prerequisites and faction relations before asserting campaign compatibility. Test shared objective completion and independent player inventory in an isolated fixture.
5. Audit ALife actor selection, object ID 0, save registries and `CALifeUpdateManager::change_level`; test distance activation around two separated players, and coordinated transitions including disconnect.
6. Exercise generic enemy selection plus poltergeist/anti-aim/aura cases against both actors; ensure server decisions produce client-local audiovisual effects without a server camera.
