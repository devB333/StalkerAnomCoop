# S04-T03 — Define and validate the initial protocol codec

Recorded 2026-10-20 UTC. **Status: Completed (2026-10-20).** No engine change
(no patch). Project code: `protocol/include/coop/proto/` (`wire.h`,
`messages.h`, `guard.h`), `protocol/src/proto/` (`messages.cpp`, `guard.cpp`),
`tests/protocol/`. Specification: [Wire format v1](../network-protocol.md#wire-format-v1).

## Question

**Acceptance** (plan.md S04-T03): length, count, version and identity bounds
enforced; obsolete epochs and recycled entity generations rejected.
**Validation:** round-trip and truncation/oversize/fuzz fixtures; unknown
version/type handling. **Risk:** native serializers may assume trusted
packets; never expose unchecked deserialization.

## Result

Accepted. Protocol v1.0 has 15 message types on 6 channels (amended by
[S04-T04](S04-T04.md): Hello's auth-proof blob became a 32-byte client nonce,
and AuthChallenge and AuthProof were added, so 17 types). A stateless
bounded decoder sits in front of a stateful per-connection guard. Final build
**proto-build-7** (0 warnings at `/W4 /WX`). Final runs: **pt-3** passed 20/20
protocol tests, with 1,901,113 fuzz mutations and 500,000 noise inputs;
**tr-7** passed the S04-T02 transport suite 51/51 against the same build.

## Design decisions

1. **A short header after the handshake.** The draft envelope
   (`network-protocol.md`, "Identity and envelope") put campaign and session
   ids (32 bytes) in every message. The transport connection already carries
   the session, so v1 binds the identities once in Hello/Welcome. Each later
   message carries only `type, flags, length, epoch, sequence` (24 bytes).
   Epoch fencing is unchanged.
2. **Each type has one channel and one sender.** The codec defines the
   channel layout (`transport_config()`) that the transport consumes. A
   message on another channel, or from the wrong side (a client sending a
   Welcome or Spawn), is refused before its body is read.
3. **Two layers.** `decode()` is stateless and bounds everything inside one
   message: header, lengths and counts before allocation, enums, float
   finiteness and ranges, zero identities, reserved bits, trailing bytes and
   cross-field rules. `StreamGuard`/`EntityTable`/`ResyncTracker` hold the
   per-connection state: sequences, epochs, generations, resync progress.
4. **One canonical encoding.** `encode()` runs `decode()` on its own output
   and refuses anything the receiver would refuse. The fuzz test checks the
   converse: every accepted input re-encodes to the same bytes.
5. **Opaque blobs stay opaque.** Spawn `state` (≤ 2,048 B), action `params`
   (≤ 256 B) and event `payload` (≤ 1,024 B) are bounded byte strings. Their
   contents are decoded later by kind-specific bounded codecs (S05-T02,
   S06, S08). This codec never passes them to a native serializer, so no
   native read sees unchecked network bytes.
6. **Hello's layout is frozen across majors.** A server can therefore decode
   a different major's Hello and answer with Reject `VersionMismatch` instead
   of dropping it. Minor versions negotiate down; later additions are
   optional types (bit `0x8000`) that older peers skip.

## Acceptance against the plan

- **Length/count/version/identity bounds enforced:** codec/field-limits,
  codec/values, codec/versions, and the fuzz pass (no out-of-bounds read; no
  accepted message outside its schema, because each re-encodes canonically
  through the refusing encoder).
- **Obsolete epochs rejected:** guard/handshake-and-epochs (dropped and
  counted; a future epoch is a violation).
- **Recycled entity generations rejected:** guard/entity-generations.
- **Unknown version/type:** codec/versions, codec/unknown-type-and-header.
- **No unchecked deserialization:** decision 5. Blobs are bounded and opaque
  here.

## Limits

- Entity generations on the wire are the incarnation counter the server's
  replication will assign (S05-T02). The Stage 3 registry's `EngineEntityKey`
  generation is per engine id; the mapping is S05-T02's.
- What the build id and content digest cover, the auth proof's contents and
  rate limits are S04-T04's. The heartbeat's timing is S04-T05's.
- Snapshot components are a first set (transform, velocity, health, state
  bits); S06-T02 extends them in a later minor (as optional types or a new
  major).
- The guard runs one set per connection, on the owner thread; the
  integration test used one server guard for a single session.
- No sanitizer (see S04-T02). The guard page catches over-reads; it does not
  catch reads before the buffer start (the reader only moves forward) or
  memory errors outside decoding.
- One host, loopback, as in S04-T01/T02.
