## What was missing

- The party task lived only in the server's task manager: a client's PDA
  showed it only if its own checkpoint held it, never its pooled count,
  never its completion while that client was in the world (L41). Worse, a
  client's checkpoint copy of a task ran its own logic: `CGameTaskManager::UpdateTasks`
  evaluated it every frame and a completion would run the task's Lua
  callbacks (`task_manager.task_callback`, rewards) on the client.
- Map spots the scripts made on the server (`level.map_add_object_spot[_ser]`,
  the quest's bonus stash in `treasure_manager.create_random_stash`) stayed
  on the server's map.
- A player's news queue was skipped on its rejoin (the presentation cursor
  jumped to the newest record, `send_presentation`).
- The anchor (participant 1's actor) dying left the party task with a dead
  holder: the turn-in refused NotActive for good (L42).
- **Found by pq-5:** a server restart after participant 1 had respawned did
  not start: the startup identity check (`CampaignIdentityFixture.cpp`)
  required the saved single-player actor, now participant 1's old body, to
  be held by a participant (`slots-full`, stage `campaign-identity-failed`).
  Present since S07-T07's respawn; its runs had not restarted after
  participant 1's respawn.

## The changes

| Part | Server | Client |
|---|---|---|
| Party task (L41) | CampaignEvent 11: every party task's id, state, pooled count and need, title, description, icon, map location, priority; sent when it changes and to a client entering the world; finished tasks kept (newest 16) so a client that was loading learns the completion | a presentation copy in its own task manager (`GiveGameTaskToActor` with no infos or functors), the title "… (n/N)", completed by the server's state |
| No client task logic | — | a co-op client evaluates no task (`UpdateTasks`), runs no task infos or functions on a state change (`CGameTask::SetTaskState`), and its state callback shows only the installed news line (`news_manager.send_task`) |
| Map spots (L41) | `level.map_add_object_spot[_ser]`, `map_change_spot_hint`, `map_remove_object_spot` on the server: a presentation record to every player, and the current set kept for a client entering the world | applies them to its map |
| News (L41) | on a rejoin, the news recorded for that player while away (the newest 20) are sent first | shown as usual |
| Anchor death (L42) | the turn-in runs in participant 1's live actor, whichever body it is (refused 18 while participant 1 is dead); the task's script data stays in its holder's store; after a restart a task whose data the original body's store holds is rebuilt on it; a respawned actor gets the old body's info portions | — |
| Restart after participant 1's respawn | the identity check accepts the saved actor when it is dead and held by no participant (a former body) | — |
