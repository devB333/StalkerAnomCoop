# S02-T05a — Game persistent object with no device

Recorded 2026-10-18 UTC. **Completed.** The campaign server constructs the real
`CGamePersistent`, runs its app start, parses the fixture's game parameters, and
disconnects and tears down cleanly. It has no graphics device, window, input or
sound device. Every GPU resource and ambience sound the native path would create
is skipped and counted.

No level, server, ALife, Lua world or object exists yet. Parent S02-T05 stays In
Progress; S02-T05b–d follow.

## Problem (native source)

The persistent object is the owner of `m_game_params` (read by `net_start1` and
the ALife constructor) and of the environment. Constructing it natively crashes
with no device at several points, all traced from source before the change:

1. `CEnvironment`'s `FactoryPtr<IEnvironmentRender>` member: the render object's
   own constructor creates two textures through `DEV`
   (`Layers/xrRender/dxEnvironmentRender.cpp:207-211`). This was the first
   crash, earlier than the `OnDeviceCreate` call noted in the context document.
2. `OnDeviceCreate` and environment `load()`: sky/cloud shaders, the tonemap
   texture, rain (`CDetail` mesh shader and ambient sound), lens flare and
   thunderbolt shaders, plus per-descriptor sky/cloud textures and ambient sounds
   (`Environment_misc.cpp`, `Rain.cpp:47`, `thunderbolt.cpp:83`).
3. Resource destructors call `DEV->_Delete*` unconditionally
   (`Layers/xrRender/Shader.cpp:16-49`), so teardown crashes even when nothing
   was created.
4. `IGame_Persistent::~IGame_Persistent` verified and freed
   `m_textures_prefetch_config`, which the constructor never initialised
   (`IGame_Persistent.cpp:74-76`).
5. `CGamePersistent::OnAppStart` reloads materials (asserting the library is
   empty), re-runs `init_game_globals`, and creates `ui_core` (cursor, 11 fonts),
   `CMainMenu` and the inventory UI shaders (`xrGame/GamePersistent.cpp:196-207`).
6. `CDetail::Optimize` reads `HW.Caps` for vertex-cache reordering
   (`DetailModel.cpp:123-136`); observed crash in `smoke-36`.

## Change

Patch `0008-persistent-without-device.patch`
(SHA-256 `a6f3bc362e83644a034a8ced6ff53e9e44422f70f35689adc54ee9dedc246082`).

**Renderer, CPU-only mode (`CpuOnlyResources`):**
- `resptrcode_shader::create` (both overloads) and `resptrcode_texture::create`
  (`dx10SH_Texture.cpp`, the DX11 build's file) skip and count.
- `dxEnvironmentRender` constructor and `OnLoad` skip their direct texture
  creation; `OnDeviceDestroy` tolerates null sky textures.
- The seven resource destructors skip `DEV` when nothing could have been
  registered.
- `CDetail::Load` skips `Optimize()`; the mesh keeps file order.
- `cpu_models_stats` reports `skipped_textures`.

**Engine:**
- Environment ambience sounds (rain, thunderbolt, ambient channels and effects)
  are created only when `::Sound` exists; otherwise
  `g_skipped_environment_sounds` counts them. These are presentation ambience,
  not AI stimuli; the AI-hearing layer is S02-T05c.
- `IGame_Persistent` initialises `m_textures_prefetch_config` and the destructor
  no longer verifies it.
- `CCampaignServerClock` always owns the scheduler slot at HIGH+1, because the
  server never registers the persistent object's own presentation frame.

**xrGame, campaign branches (`g_campaign_server`):**
- `OnAppStart` runs only `IGame_Persistent::OnAppStart` (environment load,
  prefetch config) plus `ScriptWallmarksManager`; materials, game globals and the
  script engine are already the server's own services.
- `OnAppEnd` mirrors that.
- `OnGameStart` records the game type and skips `LoadTitle`/`Prefetch`.
- `Disconnect` tolerates a null `::Sound`.
- `RegisterModelMaterials` counts registrations on both paths, so the model
  fixture's registration check holds after the persistent object exists.

**Campaign smoke:**
- A `persistent` service after the registries: `LALib.OnCreate` (native order),
  `NEW_INSTANCE(CLSID_GAME_PERSISTANT)`, removal of its frame registration, then
  `OnAppStart`. Stop reverses it.
- A `persistent-fixture` check: environment data loaded, `PreStart`/`Start` with
  `player - autosave/single/alife/load` parsed into `m_game_params` and
  `eGameIDSingle`, `Disconnect` resets the type, no main menu, device absent and
  textures skipped.
- GameState now reports `level-context-required`, the next unmet prerequisite.

The series reconstructs all 35 changed files in `builds/stage2/patch-check-09b`
(`builds/logs/patch-reconstruction-09.json`).

## Limits

- **No frame work yet.** The persistent frame (`CGamePersistent::OnFrame`) is
  never run. Its CPU part that gameplay needs, the environment `lerp` that feeds
  AI fog/far-plane vision, is not yet driven (B10). S02-T05d owns that split.
- **Environment modifiers sample the camera position** (`Environment.cpp:543`).
  A server has no camera; S02-T05d must decide what AI vision samples.
- **Ambience sounds skipped, not replaced.** The 486 skipped sounds are rain,
  thunder and ambient beds. AI-audible stimuli (footsteps, impacts, whines) are
  a separate layer (S02-T05c).
- **`LoadTitle` still reaches `pApp`.** ALife and level loading call it; the
  server has no `CApplication` yet (S02-T05b).
- **Client built, not run interactively.** The client's default paths are
  unchanged; the renderer guards are inert when CPU-only mode is off.
