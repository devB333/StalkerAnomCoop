# S05-T02 — Replicate entity lifecycle and initial world snapshot

Recorded 2026-10-20 UTC. **Status: Completed (2026-10-20).** Source
`builds/build_1/engine-work` at `c57fe5b9` with patches 0001–0028; protocol
v1.1 (`proto-build-15`). Design:
[co-op session, world replica](../coop-session.md#client-world-replica-s05-t02).

## Question

Plan.md S05-T02: server spawn/despawn/tombstones and an initial snapshot at
a revision watermark; buffer dependent events during join; map stable ids to
local engine objects with generations; bounded snapshot chunks.
**Acceptance:** both clients have matching authoritative entity identities;
a late join cannot resurrect destroyed entities or miss in-flight changes.
**Validation:** join during spawn/despawn; reorder lifecycle versus
snapshots; compare canonical id/state summaries.

## What was built

- **Initial snapshot = a native checkpoint.** When a player joins and its
  actor is online, the server saves `coop-join-N` through its own save path
  (`M_SAVE_GAME`, as S02-T06d), and streams one blob: the `.scop` and
  `.scoc`, the online set at the watermark (engine id → entity id and
  generation) and each participant's actor id. ResyncBegin (watermark,
  SHA-256, sizes) on the control channel, 60 KiB chunks on the bulk channel
  below a 160 KiB backlog, ResyncEnd (CRC-32). The client holds ResyncEnd
  until every chunk has arrived (separate lanes) and checks the CRC and hash.
- **Lifecycle.** Each tick the server compares its level's online ALife
  objects with what it published: `Spawn` (entity ref from the registry,
  section, transform, state = the native `Spawn_Write` packet, ≤ 16 KiB) when
  one comes online, `Despawn` OutOfRange when it goes offline and Destroyed
  when it leaves ALife; parents spawn before children, children despawn first;
  a commit id per event; each player streaming or live gets every event after
  its watermark, paced below 512 KiB of lifecycle backlog. Every event is also
  written to `coop-lifecycle.csv`.
- **Client replica** (`xrGame/CoopReplica.{h,cpp}` and hooks): the client
  writes the checkpoint as its saved game and starts it through the role
  guard (one permitted start), polling the link from the engine's loading loop
  (`device.cpp`). Then:
  - ALife runs no offline simulation; online/offline follows the server's
    events (the object, or its squad, switched when the event applies; a
    2-s reconcile pass catches up anything missed).
  - Every object except the local participant's actor and what it carries is
    spawned **non-local**, so NPCs take the engine's `Remote()` path (no AI
    think). The local participant's actor is the player entity
    (`M_SPAWN_OBJECT_ASPLAYER`) on its own client, whichever slot it holds,
    and is sent to the level first.
  - The client's in-process server refuses spawns, world control and every
    game event from its own level; `spawn_item` and `release` refuse anything
    replication did not ask for; only the local actor gets the single-player
    actor binder.
  - Known entities (in the checkpoint) switch online with the server's
    position; unknown ones are created from the server's native spawn packet
    through the engine's own path (`xrServer::Process_spawn`), keeping the
    server's engine id; Destroyed releases through `GE_DESTROY`. Events at or
    below the applied commit are ignored; `EntityTable` refuses recycled
    generations.
- **Comparison:** the client writes `coop-world-final.csv` (engine id, entity,
  generation, section, in the server's online set, present on its level);
  `tools/compare-coop-world.py` replays the server's lifecycle log to the
  client's applied commit and compares.
- **Churn fixture** (`--churn N`): the server spawns a medkit beside
  participant 1 every N s and releases it N/2 s later.

## Limits

- **No state after spawn.** NPC and item positions on a client are their
  spawn (or checkpoint) positions; remote NPCs do not move or animate from the
  server yet (snapshots: S05-T03 for actors, S06-T02 for the rest). Health,
  inventory transfers between owners and other state changes are not
  replicated (S06/S08).
- Transient non-ALife objects (bolts, projectiles) are not replicated
  (Stage 6 combat).
- The client keeps its checkpoint copy of offline objects (stale offline
  positions; the PDA map would show them, S10).
- On a client whose player is not the server's script actor (player 2), the
  `.scoc` script state (tasks, money and other `db.actor` data) is player 1's
  presentation (S08).
- The client's ALife scheduler update stalls after load (world-2): not
  needed by the replica; cause open.
- A join stalls the server's tick for the save (55–150 ms) and costs a
  1.8 MB transfer; one host, loopback. Native spawn packets from the server
  are trusted by the client (`Spawn_Read`): a client connects only to a server
  its player chose (R06).
- Spawn messages over 16 KiB would be skipped and counted (`spawn-oversize`):
  none in these runs.
